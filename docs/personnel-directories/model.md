# Персонал и справочники

Документ фиксирует модель этого этапа во frontend и mock. Это не контракт production-сервера.

## Что уже было

Организации и проекты разделены. Проекты скрыты из основной навигации (`surface: 'preserved'`). Создание организации в одной mock-записи добавляет роль с `ownerScope` организации и явным списком grants. Название роли полномочий не даёт. Внутри организации есть маршруты «Персонал» и «Справочник»; до этого этапа оба были заглушками и открывались через `organizations.read`. «Доступ и роли» остаётся экраном ролей и пользователей. Назначение роли идёт через assignments, не через поле сотрудника.

Отдельных сущностей подразделения, рабочего места и кадровой карточки в коде не было. `DirectoryEmployee` в mock — это симуляция внешнего источника для входа, не реестр персонала.

## Четыре разные сущности

- Сотрудник — строка кадрового реестра организации. Учётной записи может не быть.
- Учётная запись — субъект входа. Создание сотрудника её не создаёт.
- Membership — уже существующая связь учётной записи с организацией. Кадровая карточка её не добавляет и не снимает.
- Assignment — назначение роли доступа. Архивирование сотрудника его не отзывает.

Связь карточки с учётной записью хранится как `accountId` и меняется отдельной операцией. На пару `organizationId + accountId` допускается одна активная карточка. Один аккаунт может быть связан с карточками разных организаций, если в каждой есть membership. Совпадение email связь не создаёт.

## Что добавляется

Один срез `entities/personnel`. Mock хранит независимые коллекции:

- `organizationWorkspaces` — отметка, что стартовый шаблон уже применён;
- `directoryDefinitions` и `directoryEntries` — описание справочника и его ручные записи;
- `departments` и `workplaces` — организационные реестры, не копия внутри записи справочника;
- `personnelConfigs` — поля, вкладки и колонки организации;
- `employees` — карточки.

Идентификаторы справочников, полей и записей стабильны. Подпись не является внешним ключом.

Определение справочника: `id`, `organizationId`, технический `key`, название, описание, `revision`, поля, источник `manual` или `registry`, признак архива.

Запись ручного справочника: `id`, справочник, организация, значения полей, `revision`, архив.

Подразделение: название, код, родитель в той же организации. Цикл отвергается сервисом. Рабочее место: название и необязательное подразделение.

Карточка сотрудника: `id`, `organizationId`, `accountId | null`, `revision`, архив, `source` (`manual` | `integration`), `sourceId`, `externalId`, значения по `fieldId`. Системные `id`, `organizationId`, `accountId`, `revision`, `archived` не входят в конструктор полей.

## Что переиспользуется

`can` / каталог permissions / `corporate_superadmin` через уже существующее разворачивание каталога. Роль «Администратор организации» остаётся явным allowlist. Сессия, MSW `commit`, writer lock, `useUnsavedSource`, маршруты модулей организации, `PageHeader` / `PageState` / таблица / диалог / поля ввода. Конструктор форм и разделов не становится хранилищем сотрудников: у него другая модель публикации. Списки организаций, пользователей и ролей доступа не копируются в редактируемые справочники.

## Стартовый шаблон

Один шаблон `personnel-starter` версии 1. При создании организации его экземпляры пишутся в ту же mock-запись, что организация и административная роль. Повторный вызов не создаёт второй комплект, не возвращает удалённые записи и не переписывает изменённые значения. Миграция вызывает тот же сервис для организаций без отметки шаблона. Открытие страницы само данные не пишет. Новая версия шаблона на уже инициализированные организации не накатывается.

Пустые реестры: подразделения, должности, рабочие места. Статус квалификации — три редактируемые записи: «Не указано», «Подтверждена», «Требует подтверждения». Это информационное поле. Прав и допуска к работам оно не даёт.

Обязательны только имя и фамилия. Email, подразделение, должность и рабочее место не обязательны, пока справочники пусты.

Колонки реестра: ФИО, подразделение, должность, email, состояние записи.

Фотография не входит: отдельного хранилища файлов сотрудника нет, base64 в карточку не пишется. Допуски, обучение, медосмотры и документы не показываются.

## Права

Отдельные коды, без вывода одного из другого:

- `personnel.read`, `personnel.create`, `personnel.update`, `personnel.archive`
- `personnel.structure` `update`
- `personnel.account` `update`
- `directories.read`, `directories.update`, `directories.archive`, `directories.delete`
- `directories.structure` `update`

Навигация модулей смотрит эти коды, а не `organizations.read`. Сервис проверяет то же действие ещё раз. Шаблон новой роли администратора организации получает эти коды. Уже сохранённые роли по отображаемому имени не расширяются: у старых ролей нет признака происхождения. Новые роли шаблона получают `origin.template = organization-administrator`. Редактирование роли этот признак сохраняет и не принимает его из тела запроса.

Удаление записи справочника и её архивирование — разные операции. Используемую запись сервис не удаляет физически. Переименование не меняет ссылки. Архивное значение видно в старой карточке и не выбирается заново.

## Mock и live

Mock: `/mock-api/directories/` и `/mock-api/personnel/`. Live эти запросы не отправляет и показывает, что контракт сервера не подключён. Успех локальной записью в live не изображается.

Чтение и запись сверяют `organizationId` с организацией записи. Чужой id в запросе не подменяется первой доступной организацией и не возвращает её данные.

После успешного создания организации клиент открывает её «Персонал» с `org` этой организации и без `project`. Ошибка оставляет форму создания. Отмена остаётся на текущей странице.

## Интеграция

Поля источника заложены в карточку и в признак `sourceOwned` у поля. Уникальность `externalId` считается вместе с `source`, `sourceId` и `organizationId`. Ручной API не принимает смену источника и не переписывает локальные поля. Поле, которым владеет источник, сервис не даёт изменить вручную, пока источник карточки — `integration`. Кнопки подключения 1С нет.

Полное корпоративное наследование шаблонов, перевод сотрудника между организациями, формулы и циклическая синхронизация справочников в этот этап не входят.

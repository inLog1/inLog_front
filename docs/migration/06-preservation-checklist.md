# Сохранность возможностей

В графах фиксировать: было проверено до / стало после / известно неработающим / ещё не проверено. Нельзя считать весь список исправным по факту наличия кода.

## Конструктор
- Открытие /admin/constructor с org в URL, корректная организация при reload/back/forward.
- Выбор узла, nested tree, создание/изменение/удаление узла, отмена без изменения данных.
- Вкладки, добавление/редактирование/удаление, связи узлов и вкладок.
- Пять существующих типов полей, RU/EN подписи и dropdown_choices.
- Добавление, редактирование, удаление строки; ошибка сохранения не выдаётся за success.
- Комбинированный отчёт и сохранение связи отчёт → узлы/поля/строки.
- Смена организации не оставляет выбранную запись другой организации.
- ID старых данных и неизвестные metadata сохраняются адаптером; названия не используются как единственный постоянный ключ новой схемы.

## Задачи
- /scheduler/tasks с org/project/task и сохранёнными фильтрами открывается после reload.
- Список, поиск, фильтры, сортировка, пагинация, создание/редактирование/удаление.
- Kanban: движение между колонками, положение, rollback при ошибке, сходится со списком.
- Gantt: отображение, масштаб/фильтры, перенос дат и обновление других представлений.
- Детали: описание/Tiptap, приоритет, статусы, сроки, исполнители/проверяющие, теги.
- Подзадачи, комментарии, вложения, шаблоны (с учётом исходных заглушек).
- Доска: сцена сохраняется при reload и logout. Перед переносом ключей есть экспорт/восстановление; scope ключа по пользователю/проекту проверяется отдельно без стирания старой сцены.

## Остальное
- Админские организации/проекты/пользователи/участники, отчёты.
- Профиль, персональные настройки, RU/EN, light/dark.
- Уведомления: отсутствие подключения к production в mock-mode; работоспособность live-подписки проверяется отдельно.
- Геомеханика и её графики остаются достижимыми.
- Старые URL сохраняются или имеют проверенную совместимую переадресацию со всеми допустимыми query-параметрами.

В baseline/protected-files.json — хеши исходных файлов этих областей. Это способ обнаружить изменения, а не запрет на нужные исправления и не доказательство работоспособности. Каждый diff защищённого модуля объясняется текущей задачей и проверяется сценариями.

# Дизайн для последовательной реализации

## Этап 1: login.png
Макет — визуальный ориентир. Реализовать HTML/CSS-компонентами, не вставлять screenshot на страницу.
Слева спокойный заголовок и декоративные карточки данных, справа форма. Наверху inLog и название корпоративной системы. На mobile остаётся удобная форма, декор скрывается. Никакого выбора роли и общей публичной регистрации. Simulated SSO разрешён только в явно подписанном mock-mode по документу 10-corporate-login.md; на live фиктивный успех запрещён.
Шрифт: текущий системный sans stack, единый для формы и продукта; не добавлять внешний CDN. Цвета: primary #155EEF, text #14243D, muted #64748B, background #F5F8FC, card #FFFFFF, border #E2E8F0. Радиусы карточки 16px, поля 10px, высота полей/кнопок около 48px. Это целевые auth tokens; глобальный --radius/primary для старых экранов менять отдельным этапом.
Использовать существующие shared/ui Input/Button/Form и lucide-react. Декоративную схему можно собрать JSX с существующими иконками; не нужна новая генерация изображений или библиотека анимации.
В src/shared/ui/icons/LogoIcon.tsx уже есть логотип. Пока использовать его и текст inLog, не заменять фирменный знак на случайную картинку; если требуется новая версия — отдельное решение.
Видимый label «Рабочая почта» соответствует текущему API. «Не удаётся войти?» ведёт в существующее восстановление либо к корректной помощи; политика выбирается явно. Пароль входа проверяется на непустоту, а требования к новому паролю применяются при его создании, чтобы login не блокировал допустимые старые учётные данные.

## Дополнение: три состояния одного login
local — карточка почта/пароль, без SSO. mixed — как референс, оба способа. sso — заголовок, объяснение и одна основная кнопка «Войти через корпоративный аккаунт», помощь и повтор; поля пароля скрыты. Макет содержит mixed-вариант, он не обязывает корпорацию использовать оба способа.
Mock provider UI выполняется простыми существующими shadcn cards/list: «Тестовый корпоративный вход», выбор вымышленной identity, «Продолжить»/«Отмена». Не нужно генерировать ещё одну картинку или внедрять отдельную библиотеку. Это только dev/test экран.

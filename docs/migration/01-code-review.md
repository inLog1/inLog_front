## Существенные наблюдения
1. **Выход может стереть доску.** widgets/sidebar/index.tsx вызывает localStorage.clear(). features/whiteboard/model/use-whiteboard-storage.ts сохраняет сцены там же. Следовательно, этот путь выхода удаляет сцены и другие локальные настройки. Заменить на удаление только данных сессии; перенос схемы хранения доски — отдельная задача с сохранением старых ключей.
2. **Сессия определяется неодинаково.** ProtectedRoute проверяет наличие токена, RootLayout отдельно вызывает verifyToken и getMe. auth/model/selectors.ts ищет getMe в authApi, хотя endpoint расположен в userApi. Новый session bootstrap должен стать единым источником состояния, сохраняя текущий серверный контракт через адаптер.
3. **401 от логина обрабатывается как истёкшая сессия.** shared/api/clientApi.ts перенаправляет на login при любом 401. Для неверного пароля нужен ответ в форме без перезагрузки. Нельзя исключать все публичные ошибки по нестрогой проверке строки URL: выделить явную политику endpoint.
4. **Данные могут оставаться после выхода.** Sidebar сбрасывает только userApi. В store зарегистрированы восемь API, включая taskApi и adminApi; auth.logout удаляет только access token и только при успехе запроса. Нужна единая очистка всех пользовательских кешей и обоих session-ключей даже при недоступном сервере, с завершением подписок.
5. **Глобальная роль и роль членства смешиваются.** platform-role.ts содержит member/admin/super_admin; enums.ts — admin/member/editor. AdminRoute использует user.role. AdminAccess уже имеет permissions:string[], но это ещё не полная модель произвольных ролей с областью и делегированием. Не переносить admin автоматически во всекорпоративные полномочия.
6. **Контекст распределён.** Конструктор читает org из URL, задачи project/task, OrgProjectSelector дополнительно хранит свои currentOrgId/currentProjectId и записывает URL из эффектов. RootLayout загружает проекты первой организации, а не явно выбранной. При новой навигации нужны единые правила; это риск несогласованности, а не доказанный этим анализом конкретный баг переключения.
7. **Конструктор объединяет разные обязанности.** entities/admin содержит схему, данные строк и отчёты. ConstructorTable.tsx — 775 строк. Не стоит раскладывать весь код заново в первом этапе: сначала стабилизировать границу данных и подключить старый редактор к новому layout.
8. **Идентичность данных требует внимания.** generateReport преобразует строки в массивы по названиям полей. ConstructorTableWrapper затем сопоставляет их по RU/EN названиям и позиции в массиве. При новых схемах нужны стабильные fieldId/recordId; текущий формат сохраняется через адаптер, без предполагаемого соответствия узла и новой таблицы один к одному.
9. **Возможен ложный успех изменения строки.** В onEditRow ConstructorTableWrapper mutation ожидается без unwrap, затем показывается success. RTK Query mutation может вернуть error без исключения; проверить отрицательный сценарий и исправить отдельно вместе с регрессией.
10. **Связанные экраны задач требуют общей фикстуры.** Список и Gantt используют getTasks, Kanban получает GET через mutation getTaskByParams и локальный columns. Изменения должны сходиться в одном мок-хранилище. После мутаций проверять обновление фильтрованных списков и Gantt, а не только самой карточки.
11. **Инвалидация не общая для всех API.** Восемь createApi зарегистрированы отдельно. Слияние всех сразу опасно; для новых контрактов разумен один новый service с injectEndpoints. Старые API переносить позднее, по одному, с проверкой импортов/селекторов.
12. **Моки должны охватить побочные каналы.** Уведомления открывают реальный WebSocket. При mock-mode отключить живое соединение и использовать тестовый источник; обычный HTTP MSW-handler этого не делает автоматически.
13. **Разделы из макета — ещё не готовый функционал.** Оборудование, образцы и прочее добавлять поэтапно. Пустая карточка с успешным toast не считается реализованным разделом. Старые геомеханика, отчёты и профиль не должны пропасть из навигации без замены.

## Исходные проверки
- `npm ci --ignore-scripts --no-audit --no-fund`: успешно; были предупреждения peer dependencies, в том числе у вложенных зависимостей Excalidraw с React 19. Не повод обновлять весь стек в этой миграции.
- `npm run build`: успешно, TypeScript и Vite; Vite-сборка 51,09 с в этой среде. Самый крупный JS chunk около 7,94 MB minified / 2,43 MB gzip. Это не измерение скорости интерфейса.
- `npm run lint`: exit 1; **162 замечания: 131 ошибка, 31 предупреждение**.
- В scripts нет test; целевых test/spec файлов и правил Cursor в проверенном дереве не обнаружено.
- Рабочая копия после проверки чистая по git status. Результаты находятся в baseline/.

## Рекомендуемое решение
Постепенная замена: новый вход и session bootstrap → новый layout и домашняя страница → права и управление → расширение существующего конструктора через адаптеры. Старые модули остаются рабочими и достижимыми. Git сохраняет исходную точку, но сам по себе не доказывает отсутствие функциональных потерь: для этого нужны сценарии проверки.

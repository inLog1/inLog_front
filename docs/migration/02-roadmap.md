# План перехода — редакция 26 октября 2026

Работа идёт в новой ветке текущего проекта. Каждый этап имеет рабочий результат и commit; этапы не заменяют продукт целиком за один проход. Фронт может опережать backend, но DTO новых возможностей нужно обсуждать с Григорием заранее. Основной пользовательский старт — единый корпоративный вход, локальный вход остаётся настраиваемой альтернативой.

## Почему таблицы перед завершёнными формами
Сначала минимальная модель данных, затем представление формы. Дизайн формы можно делать раньше, но не создавать независимую схему полей, которую потом придётся переносить в таблицы.

## Цель к концу ноября
Обязательное демонстрационное ядро: этапы 1–4 + сохранённые рабочие задачи и старый конструктор в новом интерфейсе. Демонстрация корпоративного входа на моках помечается как симуляция. Наличие настоящей SSO-интеграции заявлять только после проверки с заказчиком.
Расширенная цель при наличии времени: таблица «Контейнеры» → форма → раздел → назначение роли → запись сотрудника. Полный универсальный процессный движок не входит в обязательство этого показа.
За неделю до согласованной даты презентации — прекращение новых возможностей и репетиции. При риске срока сокращается расширенный объём, а не проверки разграничения доступа и сохранности существующих функций. Юрий фиксирует объём и приёмку, Станислав — UI/фронт, Григорий — API и серверные правила.

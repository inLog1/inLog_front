# Приёмка

Использовать отдельный разрешённый тестовый mock-origin, не сбрасывать рабочую базу. Выдать права штатным UI, если требуется. Материалы макета не являются seed-данными.

## Функциональные сценарии
- Новый раздел: все прежние поля и действия на месте; начальные значения из emptySectionConfig не заменены примерами картинки.
- Ввести название, сохранить без ссылок — ровно существующий допустимый путь, без второго раздела от двойного клика; после reload тот же сохранённый документ. Полупустые несовместимые ссылки не пропускаются вопреки валидатору.
- Выбрать опубликованную форму и её представление; сменить форму — несовместимое представление сброшено, предупреждение видно. Загрузка/ошибка/пустой options-list различимы.
- Включить добавление, указать подпись, выключить и включить — введённая подпись не потеряна. Отключённый флажок не уничтожает значение. Образец обновляется без API-записи.
- order=0 сохраняется; отрицательные допустимые значения не отрезаны новой разметкой.
- Предпросмотр до первого сохранения недоступен; после сохранения открывает прежний адрес и не создаёт запись. Локальный образец никогда не выполняет действие.
- Подтвердить публикацию с грязным буфером: прежний save-then-publish с актуальными revisions. Ошибка save не приводит к publish. Ошибка publish не выдаётся за успех.
- Сохранение нового черновика не добавляет пункт сотруднику; публикация добавляет доступным пользователям. Изменение опубликованного черновика не меняет рабочий пункт до новой публикации. Снятие с публикации закрывает рабочий адрес, зависимости не удаляются.
- Администратор без sections.publish сохраняет разрешённый черновик и видит объяснение недоступной публикации. Неправомочный пользователь/чужая организация не получают данные через новый образец.
- Уйти по ссылке, browser back, сменить организацию при dirty: прежние диалоги и действия сохранения/отказа. Ошибка сохранения оставляет буфер. Уже начатый ответ старого org не появляется на новом экране.
- 403/409/500 и имеющаяся блокировка записи сохраняют честное сообщение, сессию/буфер в соответствии с текущим поведением. Никаких resets ради UX.

## Визуальные проверки
- 320, 390, 768, 1440 px: поля и кнопки не обрезаны, нет горизонтального overflow страницы; текст и предупреждения переносятся.
- На узком экране правая панель после полей, без фиксированной ширины; действие публикации доступно, а панель тестирования/нижние элементы его не перекрывают.
- Светлая/тёмная темы; длинное название; отсутствующее описание; showCreate=false; все реальные статусы; длинная ошибка.
- Клавиатура Tab/Enter/Space, видимый focus, labels, связанные подсказки. Неинтерактивный образец не создаёт лишних tab-stop.
- Перейти в задачи, формы и рабочий раздел: общий shell/стили остались прежними.

Существующие test/build должны пройти; lint сравнить с зафиксированным baseline. Скриншоты снимать целиком, не выдавать обрезанный участок за весь viewport. Любой непройденный сценарий явно отметить в отчёте.

# Дизайн страницы

## Что меняем
Сейчас длинные поля, одинаковые синие кнопки и разбросанные подписи мешают понять последовательность действий. Оставляем одну страницу, группируем настройки и добавляем компактный локальный образец оформления. Не вводим мастер с шагами, новые сущности или обязательные промежуточные сохранения.

## Компоновка
- Контент занимает всю доступную ширину до 1180–1240 px, с отступами 24–32 px на desktop. Не задавать фиксированную ширину всей страницы.
- Общую оболочку, sidebar, селектор организации и верхнюю панель использовать существующие. Нарисованная оболочка показывает окружение, не требует переделки меню.
- Одна строка заголовка: «Создать раздел» для нового, «Настроить раздел» для существующего; ниже пояснение «Настройте данные и вид раздела для сотрудников».
- Показать реальный статус документа. Признак несохранённых правок выводить отдельно, не присваивать новый серверный статус локально.
- Панель действий: «Сохранить черновик» secondary, «Предпросмотр» outline, «Опубликовать» primary. «Снять с публикации» — менее заметное существующее действие только в допустимых состояниях. Не прятать его без доступной замены.
- Перед первым сохранением предпросмотр недоступен; рядом короткая подсказка. Сохранение остаётся полноценным заметным действием даже без права публикации.
- Ниже сетка: основная колонка minmax(0, 1fr), правая 280–320 px; gap 24 px. Ниже примерно 1100 px — одна колонка. На мобильном поля и кнопки переносятся, правая панель следует за настройками.

## Три карточки
1. «О разделе». Название; описание; иконка и порядок в меню. Не выносить порядок в главную строку рядом с названием. Иконка — из существующего ограниченного каталога, не произвольный upload. Порядок — прежнее целое число; отрицательные значения не запрещать новым UI.
2. «Данные». Поле «Форма» и следом «Таблица · представление». Это прежний tableViewId, новое название не меняет сущность. Использовать реальные доступные опубликованные формы и совместимые представления. Подсказка: «Изменение представления обновит таблицу во всех связанных разделах». Пустые списки, ошибки загрузки, отсутствующая зависимость и смена формы должны быть различимы.
3. «Действия пользователя». Сохранить checkbox showCreate, подпись «Показывать кнопку добавления». При включении показать поле «Подпись кнопки». При выключении допустимо скрыть поле, но сохранить введённый createLabel в буфере. Подсказка: «Кнопка доступна сотрудникам с правом создания записей». Флажок не выдаёт такое право.

## Правая панель
«Вид в меню», подпись «По текущим настройкам». Это декоративный образец, построенный только из текущего локального буфера: существующая иконка, название, описание, пример кнопки при showCreate. Для пустого названия — «Название раздела», для пустой подписи — «Добавить запись» только как визуальный placeholder, без записи значения в конфигурацию.
Показывать «Разделы организации» и один пример пункта. Не утверждать его точное положение относительно других пунктов: порядок определяется реальным меню.
Никаких запросов записей, мутаций, загрузки таблицы, настоящих рабочих ссылок или обхода проверки доступа. Декоративную кнопку сделать неинтерактивным элементом, не настоящей кнопкой сохранения/создания. Не называть этот блок полным предпросмотром. Подпись: «Макет оформления. Данные здесь не загружаются».
Ниже: «После публикации» и «Раздел появится в меню сотрудников с необходимыми правами». Для нового черновика: «Сохранение черновика не добавляет раздел в меню». Для опубликованного с изменениями: «Черновик не меняет опубликованный раздел». Не говорить, что раздел увидят все пользователи.

## Визуальная система
Существующие семантические токены shadcn: bg-background, bg-card, border-border, text-foreground, text-muted-foreground, primary. Не менять глобальную палитру. Радиус 12–16 px, тонкие рамки, очень слабая тень или без неё. Заголовок 26–30 px, карточки 16–18 px, текст 14 px, подписи 13–14 px. Поля 40–44 px, textarea 88–104 px. Небольшие номера 01/02/03 помогают считывать блоки, но не обозначают отдельные этапы процесса. Контраст текста, focus-visible, Label/id и клавиатура обязательны. Поддержать светлую и тёмную темы.
Не добавлять баннеры, графики, 3D, новую боковую панель приложения, drag-and-drop, права на отдельный раздел или новый конструктор страниц.

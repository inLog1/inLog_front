# Этап 3В. Модель табличного представления

Источник решений — текущие исходники. Представление хранит только настройки отображения. Строки читаются из существующих `FormRecord`. Второй коллекции заполненных записей нет.

Legacy-конструктор и его отчёты не мигрируют в эту модель.

## Граница

Одно представление относится к одной организации и одной форме. Каталог колонок и строки берутся только из опубликованных версий этой формы. Черновик в каталог и в ответ запроса строк не попадает.

В первой версии представления общие для организации. Личных представлений и отдельного ACL у представления нет. Право представления не открывает записи: строки требуют ещё `form-records.read`, каталог полей — ещё `forms.read`.

Не входят в эту версию: объединение разных форм, вычисляемые колонки, группировки и сводные таблицы, правка строки в таблице, массовые операции, экспорт, конструктор разделов и процессов. Пользовательское переименование колонки не хранится: подпись берётся из каталога.

## TableView

Документ представления:

- стабильный `id` (`view-` и uuid); переименование название не меняет id;
- `organizationId`, `formId`;
- название и описание;
- выбранные колонки и их порядок;
- фильтры, одна сортировка, размер страницы;
- `revision` для конкурентного сохранения;
- автор и время изменения;
- `schemaVersion` настроек. Первая поддерживаемая версия — `1`. Другая версия возвращает `unknown_schema` и не читается как версия 1.

Сохраняется конфигурация. Вычисленные строки, значения записей и копии схем форм в документ не кладутся.

Системные колонки имеют отдельные id и не могут совпасть с `fieldId` формы, потому что содержат двоеточие:

- `sys:createdAt` — дата создания записи;
- `sys:author` — автор;
- `sys:version` — номер версии формы записи;
- `sys:recordId` — id записи.

Ссылка «Открыть запись» есть всегда, независимо от выбранных колонок. Видимой колонки должна остаться хотя бы одна.

Пределы конфигурации: колонок не больше 24, фильтров не больше 12, название до 200 символов, описание до 2000, поисковое значение до 200. Размер страницы — 10, 25, 50 или 100. По умолчанию 25. Смещение не больше 100000.

## Каталог колонок и версии

Каталог строится только из опубликованных версий, которые передаёт вызывающий код. Черновик в этот список не входит.

Для каждого `fieldId`:

- подпись берётся из наиболее новой опубликованной версии, где поле ещё есть;
- если в текущей опубликованной версии поля нет, колонка помечается как снятая (`retired`);
- переименование поля не создаёт новую колонку;
- значение строки читается по схеме версии самой записи.

Переход к записи открывает её `formVersionId`, а не текущую схему формы.

Если у одного `fieldId` в разных опубликованных версиях разные типы, колонка помечается как смешанная (`mixed`). Сортировка и типовые сравнения по ней запрещены. Допустимы только «есть значение» и «нет значения». Значение показывается в исходном типе записи. Текст к числу не приводится.

Для выбора:

- в записи и в фильтре хранится `optionId`;
- в ячейке показывается подпись варианта из версии этой записи;
- одинаковые подписи с разными `optionId` не сливаются;
- варианты фильтра собираются из опубликованных версий; если подписи совпали, в списке фильтра они различаются id.

Неизвестная `schemaVersion` схемы формы не читается как версия 1. Запрос строк по такой форме не возвращает значения.

## Пустые состояния

Ячейка имеет одно из трёх состояний: значение, пусто, поля нет в версии записи.

В таблице это «Не заполнено» и «Нет поля в этой версии». Ноль и `false` ими не подменяются.

Как читается существующее хранилище, без переписывания старых записей:

- текст и многострочный текст: строка после обрезки пробелов — значение; пустая строка и строка из пробелов — пусто;
- число: конечное число, включая `0`, — значение; `null` и пустая строка — пусто; строка вроде `"10"` остаётся нечисловым значением и в числовое сравнение не входит;
- дата: только календарная строка `YYYY-MM-DD`, без сдвига через локальный `Date`;
- выбор: значение — `optionId`; подпись берётся из версии записи;
- флажок: `true` и `false` — значения; отсутствие ключа и `null` показываются как пусто.

Запись формы всегда сохраняет флажок как `true` или `false`: писатель формы иное значение не принимает. Состояние «флажок есть в версии, но не заполнен» на чтении возможно только если ключа в записи нет. Старые записи из-за этого не переписываются.

Поле, которого нет в схеме версии записи, — «нет поля», даже если в `values` остался посторонний ключ. Запись, чья версия не входит в опубликованный набор, показывает поля как отсутствующие. Черновик для этого не используется.

`0` и `false` считаются значением и проходят проверку «есть значение».

## Фильтры

Фильтры первой версии объединяются только через AND. Вложенных групп и OR нет.

Операторы:

- текст, автор, id записи: содержит, равно, есть значение, нет значения;
- число и номер версии: равно, больше, меньше, есть значение, нет значения;
- календарная дата: равно, не раньше, не позже, есть значение, нет значения;
- дата создания: календарный день в первой версии считается в UTC и записывается как `utc-day:YYYY-MM-DD`. Равенство — `timestamp >=` начало суток D и `<` начало следующих суток. «Не раньше» — с начала выбранного дня. «Не позже» — до начала следующего дня, не включая его. Полная строка ISO и любой другой некалендарный текст остаются точным сравнением строк. Голая дата `YYYY-MM-DD` без пометки не переписывается молча: запрос получает `legacy_created_at`. Миграция схемы 8 переписывает только сохранённые фильтры `sys:createdAt`, значение которых уже было календарной датой;
- одиночный выбор: равно `optionId`, есть значение, нет значения;
- флажок: да / нет, есть значение, нет значения;
- смешанная колонка: только есть значение и нет значения.

Текст сравнивается без учёта регистра. Числа сравниваются как числа. Календарные даты сравниваются как строки `YYYY-MM-DD`.

Обычное сравнение не проходит, если поля нет в версии записи, значение пустое или значение нельзя сравнить в типе колонки. «Нет значения» включает и отсутствие поля, и пустое значение. «Есть значение» требует состояния «значение», включая `0` и `false`.

Неизвестный `fieldId`, недопустимый оператор и значение не того типа отклоняются. Черновые поля в каталоге нет, поэтому отфильтровать по ним нельзя.

## Сортировка

Одна колонка, по возрастанию или по убыванию. При равных значениях порядок дополнительно фиксируется по id записи по возрастанию, в том числе когда основное направление — убывание.

Пустые ячейки и отсутствующее поле всегда в конце, независимо от направления. Выбор сортируется по показанной подписи. Автор — по показанному имени. Флажок: `false` раньше `true`.

По умолчанию: дата создания по убыванию, затем id.

Смешанная колонка в сортировку не принимается.

Смена фильтра или сортировки в интерфейсе возвращает на первую страницу.

## Запрос строк

Порядок на mock service: сессия и доступ, организация и форма, записи этой формы и организации, фильтры, сортировка, страница, проекция запрошенных колонок.

Ответ: описание выбранных колонок, строки со стабильными `recordId` и `formVersionId`, `total` до отсечения страницы, `offset` и `limit`. `total` не равен длине одной страницы. UI не загружает все записи ради своей пагинации.

Несовместимая сохранённая сортировка или фильтр без временной замены даёт `409 incompatible_view` и не выполняется с молча снятым условием. Временная замена с ошибкой даёт `400 invalid_query` и тоже не подменяется сохранённым фильтром. Исправленная временная конфигурация может выполниться, пока сохранённый документ не перезаписан.

Поздний ответ принимается только если совпали организация, форма, представление, окно, фильтры, сортировка и список колонок.

## Состояние рабочей таблицы

Зафиксированные временные условия живут в query-параметрах адреса: `page`, `size`, `sort`, `filters`. Параметр `org` и остальные параметры не затираются. Отсутствующий параметр означает настройку сохранённого представления. Нечитаемый параметр — ошибка `invalid_work`: запрос не уходит и сохранённый фильтр вместо него не подставляется.

Набор в форме фильтра — локальный, пока пользователь не нажмёт «Показать». Redux хранит только кэш RTK Query по аргументам запроса. В `localStorage` копии условий нет.

Номер страницы — навигация, а не отличие от сохранённого представления. Отличие показывается, когда временные размер страницы, сортировка или фильтры расходятся с документом. Сброс убирает эти параметры из адреса и не переписывает документ.

## Permissions

Коды, область организации:

- `table-views.read`
- `table-views.create`
- `table-views.update`
- `table-views.delete`

Соседние права не включаются. Миграция добавляет строки каталога и не дописывает их в `grantIds` существующих ролей. Назначение идёт через редактор ролей этапа 3А. Capability `corporate_superadmin` операционные права не заменяет. `403` сессию не завершает.

Состав экранов:

- список представлений: `forms.read` и `table-views.read`;
- таблица и строки: `forms.read`, `table-views.read` и `form-records.read`;
- каталог опубликованных колонок: `forms.read` и любое из `table-views.read`, `create`, `update`;
- создание: `forms.read` и `table-views.create`; предпросмотр ещё требует `form-records.read`;
- изменение: `forms.read` и `table-views.update`; предпросмотр ещё требует `form-records.read`;
- удаление: `table-views.delete`; форма и записи не удаляются.

Чужой `viewId`, `formId`, `recordId` и подставленная организация не возвращают название и значения. Нет права — `403` до поиска сущности. Сущность в чужой организации после успешной проверки права — `404` без содержимого.

## Хранение

`MOCK_SCHEMA_VERSION` стал `7`. `MOCK_DB_VERSION` и namespace `inlog:mock:corporate-v2` не менялись. Миграция добавляет пустую коллекцию `tableViews` и недостающие строки каталога прав. Формы, версии, записи, роли, назначения, задачи, legacy-конструктор и история доступа сохраняются. Списки прав ролей миграция не расширяет.

Запись идёт через существующий writer lock и обработку квоты. Создание, обновление и удаление атомарны. Конфликт `expectedRevision` — `409 stale_write`, чужая ревизия не перезаписывается. Невалидная конфигурация не сохраняется.

Live: `tableViewsMode` равен `unavailable`, если режим API не `mock`. Страницы стоят за тем же барьером, что и формы: дочерние запросы не монтируются. Mock к реальному backend не обращается.

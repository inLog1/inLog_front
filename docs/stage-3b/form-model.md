# Этап 3Б. Граница модели форм

Источник решений — текущие исходники. Legacy-конструктор не переименовывается и не становится этими формами.

## Что переиспользуется

- Оболочка, реестр навигации и `workspaceHref`. Новый пункт добавляется рядом с «Конструктор», а не вместо него.
- `useWorkspaceSection` и `grantAllows`. Проверка на экране только прячет или объясняет действие. Отказ делает mock service.
- Каталог разрешений, редактор ролей и делегирование этапа 3А. Новые коды предлагаются там же. `corporate_superadmin` по-прежнему открывает управление назначениями и не заменяет операционные права форм.
- `can()` и область организации. Название роли права не даёт.
- Mock-документ, `updateMockState`, writer lock и один `commit`. Публикация и запись либо попадают в документ целиком, либо не попадают.
- RTK Query через уже зарегистрированный `platformApi`. Выход сбрасывает этот кэш вместе с остальными.
- Примитивы shadcn и токены Tailwind. Отдельный конструктор форм и плагины не подключаются.
- Чистая проверка дат календаря без перевода через локальный часовой пояс. У legacy-записей тот же формат `YYYY-MM-DD`, но это не общий тип и не общий ключ.

## Что не переиспользуется как модель

Узлы, вкладки, поля и записи legacy остаются в `constructorNodes`, `constructorTabs`, `constructorFields`, `constructorRecords`. Их API — прежние `structure-element-*` и `get-combined-constructor-data`. Ключ значения там по-прежнему собирается адаптером из имени поля.

Новая форма не читает и не пишет эти коллекции. Старые записи не получают `formId` и не объявляются опубликованными версиями. Скрытой миграции смысла данных нет.

Общий renderer и валидация новой схемы живут в `entities/form`. Предпросмотр, заполнение и просмотр записи вызывают их, а не копию. Legacy-таблица узла этот renderer не импортирует: у неё другой DTO.

## Какие сущности добавляются

Все идентификаторы строковые и стабильные. Подпись поля и подпись варианта не являются ключом значения.

- `Form` — id, организация-владелец, название, описание, id текущей опубликованной версии или пусто, служебная ревизия документа.
- `FormDraft` — одна редактируемая схема, id версии, от которой черновик отталкивался, ревизия черновика. Ревизия черновика не равна ревизии формы.
- `FormVersion` — неизменяемый снимок схемы, названия и описания, порядковый номер, дата, автор, ревизия черновика, из которой снимок собран. Повтор той же ревизии черновика возвращает уже созданную версию.
- `FormRecord` — id, организация, formId, formVersionId, значения по `fieldId`, автор, время. Вариант выбора хранится как `optionId`.

Схема явно несёт `schemaVersion`. Первая поддерживаемая версия — `1`. Другая версия не рисуется как набор полей версии 1 и не переписывается при чтении.

Поля версии 1: однострочный текст, многострочный текст, число, календарная дата, одиночный выбор, флажок. У каждого поля есть id, подпись, пояснение и обязательность. У текста — границы длины, у числа — границы значения, у выбора — варианты со своими id.

Пустое число и `0` различаются. `false` у флажка — обычный ответ. Обязательная отметка согласия в эту версию не входит: флаг `required` у флажка не означает «должно быть true». Для выбора обязательность означает существующий `optionId`.

Дата хранится строкой `YYYY-MM-DD`. Сдвиг через локальный `Date` не применяется.

## Как старое и новое сосуществуют

| | Legacy-конструктор | Формы 3Б |
| --- | --- | --- |
| Маршрут | `/admin/constructor`, `/admin/reports` | `/forms` и вложенные |
| Меню | «Конструктор» | «Формы» |
| Права | `constructor.schema`, `constructor.records`, `reports` | `forms.*`, `form-records.*` |
| Хранение | прежние массивы | `forms`, `formDrafts`, `formVersions`, `formRecords` |
| Публикация | нет | снимок версии внутри организации-владельца |

Право схемы конструктора не открывает формы. Право форм не открывает конструктор и не даёт строить отчёт. Записи форм не попадают в combined data.

Публикация делает версию доступной для заполнения в организации-владельце. Это не шаблон на несколько организаций.

Новое заполнение открывает только текущую опубликованную версию. Черновик сотруднику не отдаётся. Если за время заполнения вышла другая версия, отправка этой версии получает конфликт, введённые значения на клиенте остаются, в новую схему они сами не переносятся.

Сохранённая запись всегда читается по своему `formVersionId`: прежние подписи, порядок, типы и варианты. Правка или удаление поля в черновике и в следующей версии этот снимок не меняет.

## Состав экранов

Соседнее право само не включается.

- Список форм: `forms.read`. Неопубликованные формы и признак «есть изменения» видны только при `forms.update`.
- Создание: `forms.create`.
- Редактор черновика и история опубликованных снимков в ответе черновика: `forms.update`.
- Публикация: `forms.publish`.
- Текущая опубликованная схема для заполнения: `forms.read`. Этот ответ не содержит черновик.
- Отправка: `form-records.create`.
- Список и просмотр записей: `form-records.read`. Схема нужной версии возвращается только вместе с доступной записью.

`forms.read` не читает черновик. `form-records.read` не даёт право править схему и не заменяет `forms.read` для списка форм. Область всех этих прав в первой версии — организация. Прав на отдельную форму, строку или поле нет.

`form-records.read` означает чтение записей тех форм, которые принадлежат этой организации и доступны проверяющему в ней. Чужой `formId`, `versionId` или `recordId` отклоняется без названия и значений чужой организации.

На свежем seed коды есть в каталоге делегирования координатора, чтобы их можно было выдать через раздел доступа. В операционные `grantIds` существующих ролей они не входят. Миграция сохранённой базы добавляет пустые коллекции и отсутствующие строки каталога, но не дописывает коды в роли и назначения.

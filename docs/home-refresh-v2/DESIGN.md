# Спецификация главной

Цель — выразительный, читаемый рабочий экран без новых функций. Полный макет — ориентир визуальной иерархии. Имена, строки таблицы и число карточек на картинке не являются требованиями к данным.

## Компоновка

Сохранить существующие sidebar и header. Изменять содержимое главной. Область с padding 24–32px desktop и 16px mobile, max-width примерно 1600px. Не сужать большие таблицы из-за узкого центрированного контейнера. При небольшой площади не фиксировать высоту страницы и не прятать контент.

Один видимый заголовок «Главная» внутри текущей иерархии заголовков приложения. Не менять глобальный Header ради удаления дубля. Если заголовок страницы уже обслуживается текущим общим компонентом — использовать его и не выводить вторую копию.

Секции по порядку:
1. Заголовок и существующий системный статус, если он доступен по подтверждённым данным.
2. Приветствие с контекстом.
3. Рабочие разделы + быстрые действия.
4. Существующий блок задач проекта.
5. Доступные инструменты настройки.

## Приветствие

Высота ориентировочно 160–190px desktop, без fixed-height, режущего длинный текст. Радиус16px. Градиент от #102846 к #1D63CD. Текст белый; вторичный #D7E6FA. Заголовок 28–36px, line-height 1.15–1.25, текст 14–16px. Не делай гигантское приветствие как на лендинге.

Слева живой текст: «Здравствуйте, {имя}», подпись «Ваше рабочее пространство», подтверждённые организация/проект. Справа декоративные листы данных из welcome-background.webp. Фон не содержит пользователя или надписей, поэтому доступен всем ролям. Графика за пределами зоны текста, aria-hidden, без hit target и без анимации.

Изображение на всю поверхность с CSS overlay тёмного градиента слева либо только в правой половине поверх базового CSS-градиента. Контраст текста должен сохраняться при любой загрузке и размере. При отсутствии файла остаётся полноценный CSS-фон. Текст нельзя вырезать из макета.

Без организации: предложение выбрать её существующим механизмом. Во время загрузки — нейтральная подпись/skeleton без имени прежнего пользователя. Ошибки, forbidden, empty и not-found не превращать в обычный готовый контекст.

На mobile: графику скрыть, 22–26px приветствие, контекст переносится, высота auto. Имя/названия могут быть длинными. Не добавлять повторные селекторы в hero, если выбор уже есть в шапке; доступное действие может вести к существующему выбору.

## Рабочие разделы и быстрые действия

Desktop от 1200px: примерно 2/3 для разделов и 1/3 для действий. Средняя ширина: действия ниже или в отдельной строке. Mobile: всё в одну колонку. Не задавать фиксированную ширину в пикселях, вызывающую overflow.

Разделы — самостоятельные карточки с иконкой, названием, коротким описанием и стрелкой. Grid внутри рабочей области: две колонки, когда помещаются, иначе одна. Нет общей огромной белой рамки с двумя маленькими строками. При одной карточке не оставлять искусственную пустую вторую ячейку. Много динамических разделов — нормальные строки сетки, без произвольного скрытия.

Иконки lucide из уже установленной библиотеки: задачи — синий tile, отчёты — мягкий фиолетовый; динамические разделы — их текущие iconKey с fallback. Декоративный цвет не означает доступ или статус.

Быстрые действия используют текущий filtered список. Первое доступное основное действие primary, остальные outline/ghost. «Создать задачу» ведёт к текущей форме, «Открыть конструктор» и «Построить отчёт» сохраняют действующий сценарий. Не запускать генерацию отчёта автоматически ради совпадения текста кнопки.

## Задачи

Те же запросы, лимиты, фильтры и guards, что сейчас. Название «Задачи проекта», потому что список не обязательно персональный или отсортированный по новизне. В шапке — текущий проект, если подтверждён, и «Все задачи».

Desktop: название / статус / срок, строки 44–52px. Если сейчас компонент — список, можно переложить его в семантическую таблицу или адаптивные строки, не меняя источник данных. Mobile: название и ниже статус/срок, вся карточка доступна с клавиатуры. Не делать кликабельный tr без доступной ссылки.

Статусы читаемые бейджи. Используй действующий semantic code, если он есть. Не определяй завершённость по переведённому названию. При отсутствии надёжного кода — нейтральный бейдж с фактическим текстом. Не добавлять просрочку или вычисленные KPI.

Неизвестные сроки не подменять датой. Дату не пропускать через timezone-конвертацию, если старое поведение сохраняло календарный день. Не менять count. Loading, empty, error/retry остаются различимыми.

## Настройка

Компактные карточки существующих инструментов: формы, разделы, доступ и роли, legacy-конструктор и прочие доступные по текущему реестру. 4 колонки при достаточной ширине, 2 на средней, 1 на узкой. Иконка, подпись, краткое описание, стрелка.

Профиль и уведомления не превращать в главные рабочие карточки; доступ к ним остаётся в оболочке. Не терять ссылки на другие ранее доступные инструменты при группировке. Отдельного глобального каталога таблиц без маршрута не создавать.

## Цвета и состояния

Фон #F4F7FB, поверхности white, основной текст #14233C, вторичный #52647D, границы #DFE7F1. Primary брать из действующего theme, ориентир #1677E8. Radius12–16px, небольшая тень только у карточек. Состояния hover/focus видимы и не сдвигают layout.

Темная тема: фон около #101724, карточки #182235, основной текст #EAF0F8, secondary #B6C5DA; граница #2B3A51. Hero остаётся синим с белым текстом. Это локальные home-токены, не глобальная замена всех shadcn переменных.

Не добавлять внешние шрифты, CDN, аналитику, глобальные CSS overrides или новые библиотеки. Изображение декоративное, без новой сетевой зависимости.

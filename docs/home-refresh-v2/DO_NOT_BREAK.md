# Сохраняемые инварианты

Это визуальная задача. Не исправлять вместе с ней owner, роли, делегирование или backend. Прежняя политика могла уже быть изменена пользователем; её нельзя откатить на код из старого архива.

Сохранить:
- текущие routes, workspaceHref, org/project и поведение выбора контекста;
- can/grantAllows, системную capability, session bootstrap, logout, cache reset;
- проверки blocked/pending и отсутствие данных прошлой сессии;
- реестр навигации и динамические опубликованные разделы;
- useOrganizationSectionLinks и его currentData/guards;
- shouldLoadProjectTasks и отсутствие запросов без готового проекта и права;
- HomeProjectTasks, args useGetTasksQuery, currentData, ключи контекста и повтор после ошибки;
- requestCreateTask и существующее открытие формы;
- ссылки задач со slug именно текущего проекта;
- регистрацию API-кэшей, мок/live разделение и запрет upstream;
- базу, namespace, schemaVersion, версии форм и представлений;
- существующие локализации и переключение тем.

Не изменять:
entities/access/model/grants.ts, mock services/repository/seed/migrate, session, endpoints и DTO, маршрутизатор, package dependencies, .env, worker. Если без такого изменения задача действительно невозможна — зафиксировать причину, не ослаблять инварианты ради внешнего вида.

Ожидаемая зона: текущие компоненты главной в app/home либо их актуальные аналоги; локальные presentational компоненты/CSS; RU/EN ключи для текста главной; один новый фон в public/images/home-refresh-v2. Не переносить весь проект по FSD.

Примеры имён «Алина», «Лаборатория Б», «Проект Б-1», задач и дат на референсе не вшивать. Системный статус «Полный доступ» показывать только по текущему авторитетному признаку; название роли/email не основание. Клиенту и сотруднику не показывать owner badge.

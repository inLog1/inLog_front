# Приёмка по подшагам

## Общие обязательные проверки

- `npm test` и `npm run build` успешны; отдельно mock build/запуск с соответствующим режимом. Live build не регистрирует dev handlers/панель, live не получает вымышленные личности.
- Lint: исходно 123 ошибки/27 предупреждений. Проверить изменённые файлы, не добавлять новый долг; общий exit 1 честно указать. Не подавлять правила глобально.
- В mock нет API-трафика на backend; незнакомый mock путь 501. Проверка live-режима не требует реальных credentials: допускается контролируемый локальный stub и анализ сборки.
- Никаких localStorage.clear(), reset базы при reload или присваивания доступа по названию роли.

## 2А-0

Четыре review теста зелёные; положительный разрешённый доступ тоже работает. Проверить назначение вне scope, усиление уже назначенной роли, границы делегирования, отозванные права и blocked с существующим токеном. Deferred logout/login/SSO/bootstrap/API не меняет последующую сессию. Logout сразу закрывает рабочую область. Mock/live не читают сцены друг друга. Reset с заблокированной БД не сообщает успех.

## 2А-1

Два пользователя A/B; один проект; несколько проектов; организация без проекта; pending; blocked. Чужой/подставленный/несуществующий ID и неверный формат URL. Переключение во время загрузки, reload, back/forward, deep link и ошибки списка. Старые данные не остаются в видимом контексте, зависимые запросы до ready не уходят. Организационные разделы работают без выбранного проекта.

## 2А-2

CRUD задачи и подзадачи, статус/срок/исполнитель, комментарии и файл переживают reload. List/Kanban/Gantt согласованы. Поиск+фильтр+пагинация имеют корректный count. Одинаковые slug в A/B не связывают кэши. Отказы mutations откатывают оптимистические изменения. Задача/родитель/участник из другого проекта отвергаются. UI не скрывает отсутствие поддержки 501 успешным toast.

## 2А-3

Из существующего конструктора создать узел/вкладку/поле/объект; изменить; reload; построить отчёт из сохранённых записей. Проверить типы и обязательность, пустые значения, ссылки и переименование без потери данных. Удаление зависимостей предсказуемо. Прямой API-запрос от B/customer запрещён. Заголовок не порождает непрерывные ошибки уведомлений. Данные этапа 1 и задач остаются. Полная проверка всех legacy разделов не подразумевается: каждый непокрытый маршрут явно перечислить.

Ручной отчёт содержит пользователя, действие, ожидаемое и фактическое поведение. Unit/integration тест не выдавать за браузерную проверку. Тестировать инварианты и сценарии, а не копировать реализацию в ожидаемое выражение.

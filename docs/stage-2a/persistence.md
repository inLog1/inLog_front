# Хранение моков без потери работы

Сейчас: IndexedDB inlog:mock:corporate-v2, запись root, schemaVersion 1. Не менять namespace при каждом подшаге и не reseed существующую базу. Расширить документ задачами, словарями и конструктором через явную миграцию старого снимка. Version IndexedDB и версия документа — разные понятия. Миграция сохраняет пользователей, назначения, настройки и существующие данные; неизвестную новую версию нельзя молча сбросить. Предусмотреть экспорт снимка и понятный отказ при несовместимости.

Обязательно проверить реальный старый snapshot v1 с изменёнными ролями/назначениями, повторный запуск миграции и перезагрузку после обновления. Изменения выполняются транзакционно; не перезаписывать root устаревшим снимком при нескольких операциях. Если несколько вкладок пока не поддержаны, реализовать обнаружение/блокировку записи второй вкладкой с объяснением; простая Promise-очередь внутри одной вкладки этого не решает.

Файлы задач: Blob + метаданные в локальном IndexedDB, проверенный владелец/проект. Object URL создаётся при чтении и отзывается при освобождении; не сохранять blob: URL как постоянную ссылку. Ограничить размер тестового вложения и обработать quota exceeded без ложного успеха. Экспорт Blob потребует отдельного формата или явного предупреждения, что обычный JSON не содержит бинарные данные.

Reset очищает только namespace моков после подтверждения, не live сессию, тему и доску. onblocked — не успех: предложить закрыть другие вкладки, дождаться результата или показать ошибку. Logout не сбрасывает сиды и не удаляет рабочие данные.

Доска: новые ключи включают режим/namespace, пользователя и идентификатор сущности. Старые ключи сохраняются. Не присваивать сцену текущему пользователю из ключа без проверенного владельца. Восстановление — отдельное явное действие с экспортом/выбором; пока оно не реализовано, точно описать ограничение.

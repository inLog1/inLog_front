# Отчёт подшага 2А-0.1

1. Версия: 27 октября 2026. Ветка `migration/stage-01-auth`. HEAD `4d427a2388079f4e421d2b091a4a84cf1af64962` не менялся, работа не закоммичена. Push, reset, clean и stash не выполнялись. Пользовательский namespace `inlog:mock:corporate-v2` не сбрасывался. Незакоммичены правки 2А-0, этот подшаг и прежние материалы пакета.

2. Что работает.

- Reset своего namespace заменяет запись `root` в одной транзакции IndexedDB. Успех возвращается только после `oncomplete`. `deleteDatabase` больше не вызывается, поэтому отказ не оставляет отложенное удаление.
- Если транзакция сброса обрывается, в базе остаётся прежняя запись.
- Открытое соединение другой вкладки само по себе сброс не блокирует и базу не удаляет. Запись при этом ограничена отдельно: одна вкладка держит аренду писателя на 60 секунд. Открытая вкладка обновляет аренду каждые 20 секунд. Вторая вкладка читает данные, но изменение и сброс получают 409 `mock_writer_held`. На экране есть текст, что эта вкладка данные не меняет и базу не удаляет.
- Запись со снимком более старого `recordRevision` получает отказ `stale_write`. Более новая запись остаётся.
- Снимок документа версии 1 открывается без reset. Отсутствующий `delegationGrantIds` становится пустым массивом и так сохраняется. Уже записанный список не расширяется каталогом сида. Пользователи, роли, операционные `grantIds`, назначения, делегирование-запись, режим и фаза установки остаются. Повторное открытие документ заново не переписывает.
- Неизвестная версия документа, например 99, по-прежнему не затирается молча. Явный reset по-прежнему заменяет только выбранный namespace.
- Версия самой IndexedDB остаётся 1. Namespace не менялся.

3. Изменённые файлы и контракты.

Хранение: `src/app/mocks/db/repository.ts`, `migrate.ts`, `constants.ts`, `types.ts`, `seed.ts`, `repository.test.ts`. Документ теперь версии 2, у него необязательный `recordRevision`. Это маркер очередности записи, не право доступа.

Сеть моков и экран: `src/app/mocks/handlers.ts`, `src/app/session/SessionProvider.tsx`, `SessionScreens.tsx`, `src/features/dev-testing/ui/MockTestPanel.tsx`, `src/entities/session/model/sessionSlice.ts`, `types.ts`, `src/entities/access/model/accessApi.ts`, `src/shared/i18n/locales/ru.json`, `en.json`.

`GET installation/status/` в mock дополнительно отдаёт `writeLocked`. Для live это поле не требуется. `POST auth/dev/reset/` при чужой аренде отвечает 409 `mock_writer_held`, а не `reset_blocked`. Успешный reset по-прежнему возвращает namespace и schemaVersion; номер документа теперь 2. `POST auth/login/`, verify, logout, `users/me`, организации и проекты не менялись. Отказ `stale_write` тоже mock-only.

4. Права.

Каталог действий не менялся: действия не выводятся друг из друга, capability не является wildcard. Миграция не добавляет `g-delegate`, `g-members-read` и роль `role-members-reader` в уже существующий снимок.

Положительно на изменённом снимке версии 1: операционный `projects.read` владельца и `tasks.read` сотрудника сохраняются; явно записанный `delegationGrantIds: ['g-members-read']` у администратора лаборатории остаётся и даёт `canDelegate` только на это чтение.

Отрицательно: у роли без поля `delegationGrantIds` после миграции список пуст, поэтому владелец не получает `delegations.delegate` и не может делегировать права сида. `members.manage` по-прежнему не покрывает `members.read`. Чужая вкладка и устаревший снимок не записывают новый документ.

5. Хранение.

IndexedDB `inlog:mock:corporate-v2`, ключ `root`, версия базы 1. Версия документа 2. Версия 1 мигрирует на месте. Версия выше 2 остаётся ошибкой схемы, пока её отдельно не сбросят.

`recordRevision` при миграции старого снимка становится 0, если числа ещё не было. Обычная запись увеличивает его на 1. Reset кладёт новый сид с revision 1. Повторная миграция уже версии 2 с заполненными полями запись `root` не трогает.

Аренда писателя лежит в той же базе под ключом `writer` и действует только внутри своего namespace. Это не межвкладочная транзакция. Пока аренда жива, вторая вкладка не перезаписывает `root`. После закрытия вкладки-владельца аренда истекает не сразу, а по таймеру в 60 секунд; затем писать может другая вкладка. Очередь Promise по-прежнему упорядочивает только операции одного окна.

Reset не вызывает `localStorage.clear()`, не трогает тему, доску и live-сессию. Logout по-прежнему не чистит mock-базу.

8. Непокрытое и риски.

Handlers задач, конструктора, отчётов и platform-admin по-прежнему 501. Редактор ролей, новая главная и подшаг 01 не начаты.

Несколько вкладок не ведут одну транзакцию. Вторая вкладка может начать писать после истечения аренды, даже если первую вкладку просто свернули дольше чем на 60 секунд без запросов. Одновременная работа двух писателей не обещана.

Уже открытая браузерная база не получила новые фикстуры 2А-0: пустое делегирование так и осталось пустым. Свежий сид и явный reset своего namespace по-прежнему содержат каталог делегирования владельца и `role-members-reader`. Чтобы не потерять текущих пользователей, этот namespace не сбрасывался.

`recordRevision` защищает запись, которая возвращает целиком старый объект. Обычные мутаторы читают состояние внутри транзакции и копируют его, поэтому свой revision сохраняют.

9. Что передать backend.

Формы login, verify, logout, `users/me`, организаций и проектов те же. Сервер по-прежнему сам проверяет права. Пустой каталог делегирования не выдаёт права сида и не отменяет уже хранимую запись делегирования: запись остаётся данными, а право считается отдельно.

Предлагаемые mock-поля: `writeLocked` у статуса установки, коды `mock_writer_held` и `stale_write`. Для production это не контракт. Версия документа mock и версия IndexedDB — разные числа; неизвестную более новую версию клиент не стирает.

10. Готовность к 2А-1.

Критерии 2А-0.1 выполнены: неуспешный reset не удаляет базу позже, старый снимок мигрирует без reset и без новых прав, повтор миграции стабилен, вторая вкладка ограничена в записи и показывает причину. Подшаг 01, новая главная, sidebar и редактор ролей не начинались.

Перед 2А-1 стоит помнить: текущая браузерная mock-база уже версии 2 и без каталога делегирования сида. Новый код не должен считать пустой `delegationGrantIds` поводом заново засеять роли.

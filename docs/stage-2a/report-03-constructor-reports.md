# Отчёт подшага 2А-3

1. Версия: 27 октября 2026. Ветка `migration/stage-01-auth`, HEAD `9be407e`. Изменения не закоммичены и не отправлены. Reset, clean и push не выполнялись. Незакоммиченная работа 2А-0, 2А-1 и 2А-2 сохранена. Новая главная, оболочка sidebar, универсальный конструктор форм, редактор ролей, мастер установки и настоящий SSO не начинались.

2. Что работает. Существующие страницы `/admin/constructor` и `/admin/reports` не заменены. Hooks `adminApi` прежние: узлы, вкладки, поля, записи и `get-combined-constructor-data`. UI по-прежнему получает данные через RTK Query и не импортирует seed, handlers или mock repository.

   Мок выполняет чтение и запись узлов (`structure-element-group`), вкладок (`structure-element`, включая `multiple-update`), полей (`structure-element-field`) и записей (`structure-element-object`). Ответ combined data — исходный массив `AdminPanelReport[]`. Таблицу по-прежнему собирает клиентский `transformResponse`.

   Значения записей лежат по стабильному id поля. В legacy DTO ключ — текущее `name_en`, иначе `name_ru`. Переименование не стирает значение. Смена типа при уже сохранённом значении отвечает 409 `type_change_blocked` и оставляет значение. Удаление варианта dropdown, который ещё хранится, отвечает 409 `choice_in_use`. Пустая строка сохраняется. `blob:` отклоняется: у конструктора нет endpoint загрузки файла, в записи остаётся имя, не байты.

   Удаление зависимостей запрещено, без каскада: узел с детьми, вкладками, полями или записями, вкладка с полями, записями или входящими связями, поле с любым сохранённым значением — 409 `has_dependents`. Саму запись удалить можно при `constructor.records` `delete`.

   `multiple-update` проверяет весь список и только потом меняет состояние. Ошибка одного элемента не оставляет частичный результат. Пустой `related_structure_elements` связи не снимает: форма переименования всегда присылает пустой список. Непустой список заменяет связи и проверяет, что они принадлежат этой организации. Чужой id в body или query — 400 `invalid_relation`, документ не меняется, чужие имена не возвращаются. `stale_write` и занятый writer — 409, `QuotaExceededError` — 507, без сообщения об успехе.

   Отчёт различает состояния: ещё не построен, идёт построение, результат пуст, ошибка запроса, недостаточно прав. Смена организации сразу убирает предыдущий результат: рабочая область отчёта смонтирована с `key` организации, а поздний ответ сверяется с организацией и номером запроса.

3. Изменённые файлы и контракты.

   Новые:
   - `src/app/mocks/constructor/service.ts`, `handlers.ts`, `service.test.ts` — узлы, вкладки, поля и записи.
   - `src/app/mocks/reports/service.ts`, `handlers.ts` — combined data.
   - `src/app/mocks/notifications/service.ts`, `handlers.ts` — список, прочтение и скрытие только своих уведомлений. Websocket в mock не включался.
   - `src/features/report/report-details/model/report-request.ts` и тест — сверка организации и номера запроса.
   - `src/features/org-project-selector/model/constructor-access.test.ts` — видимость отдельных прав.

   Изменены: `handlers.ts` (композиция auth, tasks, constructor, reports, notifications, затем 501), seed, migrate, types, constants (`MOCK_SCHEMA_VERSION` 4, версия IndexedDB 1, namespace прежний), страницы конструктора и отчётов, дерево, таблица, вкладки и контекст узла, детали и дерево отчёта, `useWorkspaceSection`, RU/EN `admin-page`.

   Публичные пути и DTO `adminApi` не заменены. Внутренний id поля наружу не выходит: adapter собирает прежний объект поля и ключи записи.

   Точечные правки существующего UI и зачем они нужны:
   - Пустой список узлов больше не подменяет дерево одной надписью. Иначе первый корень нельзя создать: кнопка была только внутри дерева. Дерево и его пустое состояние остались прежними.
   - Запрос полей узла возвращает и поля вкладок: тот же query использует дерево отчёта. Таблица узла показывает только поля без `structure_element`, чтобы колонки вкладки не редактировались как колонки узла.
   - Сохранение строки теперь ждёт `unwrap`. Раньше успех показывался и при ошибке. Повторный `onEdit` без ожидания убран.
   - Значение ячейки собирается явно: число, дата `yyyy-MM-dd` и имя файла. Ноль и пустая строка больше не выпадают из payload.
   - Кнопка «Создать отчёт» видна, если есть хотя бы один узел. Раньше она требовала вложенные узлы, и узел только с вкладками отчёт не строил.
   - Недоступные действия скрыты или отключены с текстом. 403 не завершает сессию.
   - Запрос отчёта стартует после очистки контекста. Смена организации или выбора отменяет запрос, который ещё не начался. Уже ушедший ответ не рисуется, если номер или организация не совпали.

4. Права. Каталог: `constructor.schema` `read/create/update/delete`, `constructor.records` `read/create/update/delete`, `reports` `read/generate`. `create` и `delete` — предлагаемое расширение. Они не выводятся из `update` и не выдаются по названию роли. На свежем seed они есть у «Координатор» операционно и в делегировании и у «Администратор лаборатории» только операционно. У сотрудника и заказчика их нет. Миграция не дописывает эти коды в сохранённые `grantIds`.

   Порядок: сессия, активный пользователь, существование организации, право на эту организацию, затем операция. Чтение схемы не даёт читать записи и строить отчёт. Чтение записей или `reports.generate` разрешает combined data. Одного `reports.read` для построения мало. Прямой запрещённый запрос отклоняется. Заказчик не получает лабораторные схемы и записи. Опубликованные формы заявок этим шагом не делались.

5. Хранение. Namespace прежний, версия IndexedDB 1, версия документа 4. Миграция дописывает пустые массивы узлов, вкладок, полей, записей и уведомлений, если их ещё нет. Пользователи, роли, назначения, настройки, задачи, комментарии и файлы не переписываются фикстурами. Неизвестная версия больше 4 не сбрасывается. Reset рабочей базы `http://localhost:5173` не вызывался.

8. Непокрытые endpoints. По-прежнему 501 `mock_coverage_gap`: CRUD организаций и проектов, приглашения, ответ на приглашение, запросы ролей, документы пользователя, platform-admin сверх уже существовавшего. Metadata эти экраны не запрашивают. Уведомления текущего пользователя закрыты минимальным handler. Websocket в mock нет.

   Известные ограничения:
   - На свежем seed нет пользователя, который читает конструктор и не может писать. Отдельные права схемы, записей и отчётов проверены автотестом. В браузере такой сессии не было: редактор ролей этим шагом не делается. Ручная проверка потребует отдельного снимка, где в роли явно есть `constructor.records` `read` и нет `create/update/delete`; рабочую базу для этого сбрасывать не нужно.
   - Смена организации при уже построенном отчёте в браузере не прогонялась. У Лебедева одна организация. Переключение на координатора упёрлось в writer lease после перехода между страницами. В коде предыдущий отчёт снимается ключом организации и номером запроса; сверка номера покрыта тестом `reportResponseIsCurrent`.
   - После reload на 5176 появлялась плашка занятого writer. Запись в этот момент блокировалась, чтение задач и схемы оставалось. База не сбрасывалась. Lease до 60 секунд — прежнее поведение.
   - Узкий viewport накладывает панель дерева на кнопки вкладки. На ширине 1440 px кнопки нажимаются. Размеры панелей не менялись.
   - Файл конструктора хранит имя, не содержимое.

9. Backend. Нужны отдельные действия `constructor.schema`, `constructor.records` и `reports` на организации из URL. `create` и `delete` не должны подразумеваться `update`. Чужой id в body и query отклоняется так же, как чужая организация в URL, без имён чужих сущностей. Групповое изменение атомарно. Идентичность поля не равна отображаемому имени: переименование не очищает значения, несовместимая смена типа не удаляет их молча. Combined data остаётся массивом `AdminPanelReport[]`. 403 не завершает сессию. Заказчик не читает лабораторные схемы.

10. Готовность к 2Б. Существующий конструктор и отчёты на свежем mock-seed сохраняют схему, записи и отчёт через reload и не отдают их чужой лаборатории и заказчику. Блокер уже открытой базы: миграция не добавляет новые коды прав в сохранённые роли, поэтому положительные create/update там требуют seed, где эти права записаны явно. Новая оболочка и главная не начинались.

### Исправления

Доступность действий в mock считается через существующий `grantAllows` для проверенных `organizationId` и `projectId`. Название роли в расчёт не входит. В live кнопки остаются видимыми: отказ даёт сервер. Пока доступ не готов, действия записи закрыты, чтобы форма не открылась заранее.

- Создание и подзадача требуют `tasks.create`. Редактирование, статус, срок, теги, комментарии и файлы требуют `tasks.update`. Удаление задачи требует `tasks.delete`. Исполнитель и руководитель требуют `tasks.assign`. Свой комментарий правится и удаляется только автором при наличии `tasks.update`; чужой автор получает отказ до запроса.
- Нет права — кнопка скрыта или отключена с текстом из `tasks-page.no-create/no-update/no-delete/no-assign`. Открытый диалог и редактор закрываются, если право пропало. Повторная отправка при уже отозванном праве показывает ошибку и не сообщает об успехе. Проверки handlers и service сохранены.
- Статус из select уходил строкой. `updateTask` меняет статус только при числе, поэтому экран показывал «В работе», а перезагрузка возвращала «Без статуса». Перед запросом значение приводится к числу.
- Дата уходила через `toISOString()`, и локальная полночь 27 октября сохранялась как 26.10.2026. В запрос теперь уходит `yyyy-MM-dd`.
- Замена руководителя по-прежнему два запроса. Если удаление прошло, а добавление отказало, форма показывает пустого руководителя и ошибку, без сообщения об успехе. Для файла то же: если запись байтов прошла, а последующий PATCH списка отказал, кэш задачи сбрасывается и успеха нет.
- У карточки Kanban нет отдельной смены статуса кликом: статус меняет перетаскивание. Подсказка «нет права на изменение» показывается только когда `tasks.update` действительно нет.

Новые проверки: `task-operations.test.ts` (полный набор, только чтение, чужой проект, неизвестные гранты, live без скрытия, автор комментария), `task-file-request.test.ts` (FormData без заголовка Content-Type), `task-file-url.test.ts` (отзыв blob URL). В `service.test.ts` роль только с `tasks.read` получает 403 на изменение, комментарий, назначение и файл, список не меняется.

### Ограничения

- На свежем seed нет учётки, которая читает задачи и не пишет, без правки ролей. Роли не расширялись и не урезались. Чтение без действий записи и прямой 403 проверены автотестами, в браузере отдельным read-only входом не повторялись.
- Одинаковый slug `shared-sample` в проектах 1001 и 1002 по-прежнему покрыт автотестом сервиса. Соколова не открывает организацию 102; в браузере изоляция видна как переход А-1 → А-2: на А-2 остаётся только «Задача А-2».
- Частичный отказ второго запроса руководителя в браузере не вызывался: у задачи руководителя не было, назначение Власовой было одним добавлением. Поведение формы при отказе второго шага задано в коде.
- Задача только со сроком окончания не попадает на Gantt. Это фильтр `convertToGanttTasks`, данные задачи при этом сохраняются и видны в списке и Kanban.
- Writer lease до 60 секунд после перезагрузки может ответить 409 и показать баннер. База при этом не удаляется.
- Ложная подсказка на кружке статуса Kanban у пользователя с правом была исправлена в коде после просмотра доски. Повторный проход по этой подсказке в браузере не делался.

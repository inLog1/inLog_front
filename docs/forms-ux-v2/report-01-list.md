## 5. Новые условия доступности

`formListActions` не добавляет прав. Оно только выбирает первое разрешённое прежнее действие:

1. «Настроить» при `forms.update` — тот же URL редактора.
2. Иначе «Открыть заполнение», если есть `publishedVersionId`.
3. Иначе «Посмотреть записи» при `form-records.read`.
4. Иначе «Таблицы» при `table-views.read`.

Остальные разрешённые маршруты попадают в меню `⋯`. Редактор без `forms.update` не предлагается, в том числе как disabled. Неопубликованная форма не получает заполнение. Название — ссылка только на то же основное действие. Если действий нет, название — текст. Кнопки не вложены в кликабельную строку. Меню на Radix: с клавиатуры открывается Enter и закрывается после перехода.

Подпись представлений — «Таблицы», не «Настроить таблицу»: переход по-прежнему требует только чтение представлений.

Поиск, счётчики записей, автор и дата изменения в список не добавлялись.

## 8. Что реально проверено

- 390 CSS px: карточка, бейдж, «Настроить», `⋯`, `scrollWidth` 390, горизонтального переполнения нет. Таблица `display: none`.
- Тёмная тема на 390: класс `dark` на время кадра, затем возвращён `light`. Ключ `theme` остался `light`.
- 1440 CSS px: таблица 1134 px, кнопка меню на x=1359, `scrollWidth` 1440, переполнения нет. Кадр инструмента обрезал правую часть, поэтому полный вид 1440 скриншотом не подтверждаю; размеры сняты со страницы.
- Клавиатура: Enter по кнопке меню открыл меню и сфокусировал «Открыть заполнение». Переход мышью меню закрыл. Сдвиг стрелкой автоматизацией не подтвердился.
- Lock, dirty guard, v1/v2 записи и live в этом подшаге не менялись и в браузере не гонялись.
- Пустой список в браузере не снимал: форма уже была, удалять её нельзя.
- Успешный submit создания в браузере не выполнял, чтобы не оставить новую форму без удаления. Код submit тот же: `unwrap` и `routes.forms.editor`.

# Три экрана и один понятный сценарий

Путь автора: Настроить поля → Предпросмотр → Опубликовать. Путь сотрудника: опубликованный рабочий раздел → заполнить → открыть запись. Нельзя требовать от сотрудника посещать административный редактор для обычной работы.

## Общая компоновка

Сохранить текущие белый sidebar/header и синий accent. Фон рабочей области около #F5F7FA, белые поверхности, navy заголовки #17263B, secondary #52647D, border #E2E8F0. Радиусы8–12px. Локальные классы/семантические tokens, без глобальных переопределений для всего приложения.

Главный контент выровнен от общего левого края с padding24–32px desktop/16px mobile. Конструктор использует ширину рабочей области; верхняя панель, список полей и настройки не должны начинаться в разных контейнерах. Обычная запись ограничена шириной850–960px и выровнена с breadcrumb слева. Не менять глобальную оболочку ради трёх экранов.

Один понятный заголовок: «Конструктор форм», «Приём образца» или «Запись по форме …». Не «Изменить» без объекта. H1/H2 по действующей иерархии оболочки. Основной текст14–16px, title24–28px, подписи13–14px, достаточный контраст. Никаких рекламных hero или иллюстраций на этих рабочих страницах.

## 1. Список форм

Заголовок «Конструктор форм», подзаголовок «Создавайте формы и публикуйте их для сотрудников», справа «Создать форму» при forms.create.

Белая поверхность с колонками: Форма / Состояние / Опубликованная версия / Действия. Организацию из каждой строки убрать, если список действительно одной подтверждённой организации; её видно в текущей шапке/подписи контекста. Не снимать scope фильтрацию.

Основное действие автора — «Настроить» при forms.update. Прочие действия — в меню ⋯: «Открыть заполнение», «Посмотреть записи», «Настроить таблицу» с исходными правами и published conditions. Если у человека нет update, выбрать понятное разрешённое действие, например «Открыть заполнение»; не выводить disabled Настроить как единственный путь.

Название может быть ссылкой только на реально доступный адрес. Не вкладывать кнопки в кликабельную строку. Меню доступно с клавиатуры и закрывается после перехода. Статусы спокойными бейджами: Черновик / Опубликована / Есть изменения — по текущим фактам DTO. Версия отсутствует — «Не опубликована», не v0.

На mobile — карточка с названием, статусом/версией, одним главным действием и ⋯, а не растянутая таблица из пяти колонок. Empty: пояснение и существующая кнопка создания; без права create — пояснение без фальшивого действия. Не добавлять поиск и статистику, если их нет.

## 2. Редактор

Сверху ссылка «Все формы», название формы, достоверные статусы публикации и сохранения. Действия «Сохранить черновик» / «Предпросмотр» / «Опубликовать» не стоят вперемешку с ссылками на записи.

Локальные панели — «Поля формы» / «Предпросмотр». Переходы «Записи» / «Таблицы» — обычные ссылки на существующие routes, только при правах. Они проходят dirty guard; нельзя имитировать переключение локальной вкладки, теряя несохранённые данные. Если вкладки-навигация выглядят единообразно, семантика роли tab vs link всё равно должна быть корректной.

Маленький блок названия и описания сверху. Рабочая сетка: слева280–320px список полей с Добавить поле, справа гибкая область настроек. Строки полей с понятной подписью/типом, выделение светло-синее, не ярко-бирюзовое. Порядок сохраняют действующие вверх/вниз. Выбор поля не изменяет данные.

Настройки выбранного поля: заголовок, подпись, тип, пояснение, обязательность, ограничения и варианты. Все нынешние типы поддерживаются. «Удалить поле» внизу карточки как отделённое destructive действие; прежний handler сохраняется. Если подтверждение уже есть, не убирать. Удаление относится к черновику, не к опубликованным версиям и записям.

На mobile локальные панели «Поля» / «Настройки» / «Предпросмотр»; при выборе поля можно открыть настройки, но buffer, порядок, preview values и ошибки не теряются от переключения. Верхние действия переносятся, панель не перекрывает поля; нижний padding учитывает sticky bar и testing.

Публикация — сохранённое текущее поведение, включая save dirty draft перед publish. Можно назвать «Сохранить и опубликовать», когда фактически выполняются оба шага. Диалог текущей сводки изменений сохраняется. Объяснение: «После публикации сотрудники смогут заполнять новую версию. Ранее сохранённые записи останутся без изменений». Не обещать транзакцию двух запросов: save может завершиться, а publish отказать; это нужно честно показать.

## 3. Просмотр записи

«Запись по форме “…”», бейдж «Только просмотр», рядом «К списку записей» и существующий возврат в раздел. Метаданные дата/автор/версия в компактном блоке.

Белая карточка документа с label/value. Убрать звёздочки обязательности, validation help и disabled inputs из режима именно сохранённой записи. Числа/даты/выбор/флажок выводятся через общую схему форматирования, варианты по optionId из record.schema. 0, false, пустое значение и отсутствие поля не смешиваются. Многострочный текст сохраняет переносы, длинные значения переносятся. Только обычный текст, без HTML injection.

Общий FormRenderer получает явный mode/presentation для записи либо текущий аналог. readOnly fill и preview НЕ должны случайно стать документом только потому, что тоже readOnly. Default совместим с нынешними вызовами. Не дублировать validation/schema logic во второй реализации.

## 4. Writer — отдельное состояние

В mock на экранах форм использовать текущие подтверждённые mockWriteLocked/mockWritesUnavailable или актуальный аналог. Не объявлять отсутствие флага разрешением записи до завершения проверки, если текущая модель явно различает unknown/ready.

Плашка внутри страницы: «Режим просмотра» / «Другая вкладка сейчас изменяет тестовые данные. Закройте её и повторите проверку». Кнопка «Проверить доступность» повторяет существующий status query; не захватывает lock принудительно, не делает logout и не очищает draft.

При подтверждённой недоступности блокируются create/save/publish/удаление поля/изменение порядка и прочие edit controls. Просмотр/preview/navigation по-прежнему доступны по правам. Уже введённый buffer не удаляется; пользователь видит, что изменения не сохранены. Нет блокировки только из-за недостатка прав на publish: права, busy и writer — разные причины с разными объяснениями.

Это локальный UX форм. Глобальное поведение всех экранов и алгоритм writer lock не менять. Live не вызывает mock-status endpoints. Серверная проверка остаётся обязательной на каждой записи.

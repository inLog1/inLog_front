# Отчёт: первая установка на моках

Commit и push не выполнялись.

## Что изменилось

Демонстрация остаётся в `inlog:mock:corporate-v2` и по-прежнему открывается по умолчанию. «Моя тестовая установка» — отдельная база `inlog:mock:personal-v1`. Выбор сценария пишется в `inlog:mock:scenario` и не переключает уже открытую вкладку: смена завершает сессию, отпускает writer lock этого документа и перезагружает страницу. Сессия, черновики и доска разделены по сценарию. Одинаковый `userId` не переносит чужие локальные данные.

Пустая установка не получает пользователей, роли, назначения и рабочие данные. В ней есть только технический каталог известных permissions. Повторное открытие настроенной установки её не засеивает. Сброс «Начать мою установку заново» чистит только личную базу через транзакцию repository. `localStorage.clear()`, удаление IndexedDB и force takeover не используются. Отказ writer lock не меняет запись и не считается успехом.

Мастер «Первичная настройка inLog» создаёт корпорацию, первого пользователя, локальный проверочный материал пароля и `corporate_superadmin` одной записью. Идентификатор корпорации назначает запись, не клиент. При нуле организаций и проектов суперадминистратор может создать первую организацию. Повторный запрос владельца не создаёт. Если установка сохранилась, а сессия не выдалась, дальше обычный `/login`.

Пароль владельца проверяется через Web Crypto SHA-256 с солью. Открытый пароль не хранится и не попадает в dev-список. Общий fixture-пароль остаётся только у демонстрационных аккаунтов.

Организация создаётся в `/settings/organizations-and-projects`. Тип — лаборатория или организация-заказчик. `organizations.create` — отдельное разрешение каталога, оно не дописывается в сохранённые роли и не следует из назначений. После создания адрес получает `?org=`. Проект для форм, таблиц и разделов не требуется.

«Корпоративный справочник — симуляция» добавляет строку источника и синхронизирует профиль. Это не 1С. Роли, назначения, capability и пароль владельца синхронизация не меняет. Почта сама по себе учётные записи не связывает. Кадровый идентификатор и `providerId` + `externalSubject` — разные вещи.

Доступ по-прежнему выдаётся и снимается в «Доступ и роли». После назначения есть «Скопировать адрес входа»: это обычный `/login` без токена и без письма.

Схема документа — 9. Миграция не очищает данные и не раздаёт новые права сохранённым ролям.

## Проверки

- `npm test`: 44 файла, 199 тестов, все прошли. В том числе прежние доменные тесты и `src/app/mocks/first-run/service.test.ts` (11 тестов): две базы, сброс только личной, заморозка namespace, атомарная настройка и повтор, владелец без организаций, пароль владельца, отсутствие секрета в DTO, идемпотентная синхронизация, отсутствие ролей и связи только по почте, запрет обычному администратору, отказ writer lock без записи.
- `npm run lint`: 148 проблем (122 ошибки, 26 предупреждений). Это прежний долг (`no-explicit-any`, `only-export-components`, `no-require-imports` и другие старые срабатывания). Новый код под него не подгонялся и весь долг не исправлялся.
- `npm run build` и `npm run build:live` прошли. В mock-сборке маршруты настройки и справочника лежат в отдельных чанках мастера и панели, не в основном index. В live-сборке строк `installation/setup/`, `auth/dev/directory`, `auth/dev/personal/reset` и `auth/dev/release-writer` нет.
- После этих сборок исправлен переход сразу после мастера: сессия больше не остаётся на старой фазе «не настроено», пока запрос статуса ещё не догнан. `npx tsc -b` после этой правки прошёл. Повторный vite-build после неё не запускался.

В браузере на `npm run dev:mock` проверено: переход в личную установку, мастер, вход владельца после перезагрузки при нуле организаций, кнопка «Создать первую организацию», диалог с типом «Лаборатория», появление лаборатории в `?org=1`, отсутствие кнопки копирования пароля у этого владельца, пункт лаборатории в симуляции справочника, сброс только личной установки с возвратом мастера, возврат в демонстрацию с прежними демо-аккаунтами. Демонстрационная база не сбрасывалась. Другая вкладка держала её writer lock; сообщение об этом осталось, данные не удалялись.

В браузере не проходились: корпоративный вход сотрудника до и после назначения, конструктор формы с «Номер образца» и «Масса», публикация формы, табличное представление, раздел, запись `ОБ-001` с массой 0, перезагрузка этой записи и отзыв назначения. Эти шаги описаны в `docs/first-run/manual-flow.md` и остаются для ручного прохода.

## Ограничения

Симуляция справочника не подключена к 1С. Mock SSO не является OIDC или SAML. Письма не отправляются. Одноразовый токен приглашения и установка пароля сотрудником в этот этап не входят. Увольнение и приоритет блокировок не реализованы: отсутствующая в очередной загрузке строка никого не удаляет.

Live эти mock-маршруты не вызывает. Контракты в `docs/first-run/mock-contracts.md` предложенные, не согласованные с backend.

Проверяемая сессия в этой вкладке демонстрации завершилась при возврате из личной установки. Сама демонстрационная база не очищалась; для продолжения работы нужен обычный вход.

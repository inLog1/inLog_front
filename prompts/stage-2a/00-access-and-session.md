# 2А-0 — исправить границы доступа и сессии

Прочитай REVIEW_RU.md, docs/stage-2a/access-policy.md, текущие grants.ts/types.ts, mocks/auth/flow.ts, handlers, SessionProvider, perform-logout, authSlice, sso, storage и текущие тесты. Не добавляй пока доменные handlers задач/конструктора.

1. Скопируй review/review-boundaries.test.ts в src/app/mocks/auth/review-boundaries.test.ts и воспроизведи 4 падения. Затем исправь причины. Делегирование — право выдать определённый набор разрешений; оно не добавляет операционные права получателю. can и canDelegate/assign — разные проверки. Человек может иметь оба вида полномочий явно. Если старый тест утверждает обратное, исправь его смысл и добавь положительный пример правильного делегирования, сохрани отрицательный.
2. Проверяй projectId → organizationId → corporationId по каноническому реестру. Противоречивые или неизвестные ссылки отвергай. Аналогично назначение роли не может иметь подставленную область. Проверяй полномочие управлять назначениями И весь набор выдаваемых прав в области назначения. Запрети повышение собственных прав через роль, выход за scope и неразрешённое дальнейшее делегирование. Название роли не выдаёт системную capability. Corporate capability обрабатывай явно в соответствующих операциях одной установки, не превращай её в wildcard у любой роли.
3. Объедини проверку аутентифицированного активного субъекта для защищённых mock операций: блокировка после входа запрещает данные и изменения. Session/access может отдавать минимальную информацию для экрана blocked. Не утечь списками организаций/проектов при blocked/pending. Dev-панель остаётся отдельным mock-only механизмом тестирования.
4. Проверь и исправь статические риски сессии из REVIEW: немедленное локальное закрытие при logout; очистка/отмена запросов и кэшей; best-effort удалённый logout с захваченным старым токеном без влияния на новую сессию. Поздние login/SSO/bootstrap/401/ответы API не воскрешают сессию и не стирают новую. Освобождай подписки initiate. Добавь тесты с контролируемыми deferred promises без sleep.
5. Добавь режим/namespace в новую версию ключей доски и гарантируй сброс локального состояния холста при смене контекста. Не удаляй прежние ключи и не копируй их молча текущему пользователю. Переход существующих сцен опиши как явное восстановление; UI восстановления можно оставить отдельным шагом.
6. В mock заблокируй API-запросы к известному live origin и случайным абсолютным API URL. Сохрани загрузку assets/HMR. Проверь блокировку без реального сетевого вызова. Исправь ложный успех reset при onblocked; объясни ограничение нескольких вкладок и не обещай межвкладочную транзакционность без реализации.

Готово: исходные сценарии остаются рабочими; четыре дополнительные проверки зелёные; тесты поздних ответов и реального запрета операции после блокировки проходят; нет новых lint ошибок в изменённом коде. Новых экранов и mock-доменов пока нет.

Общие условия: React + Tailwind + shadcn + RTK Query + FSD сохраняются. Не переносить все папки, не переписывать задачи/конструктор, не менять production DTO ради удобства моков. Новые proposed endpoints отметить как mock-only. UI получает данные через RTK Query, а не импортирует сиды и handlers. Композиция приложения и запуск MSW — app; доменные типы и API — entities; пользовательские действия — features; shared не импортирует app. Не создавать универсальный движок до появления потребности. Минимальные точечные исправления старого кода допустимы с объяснением и проверкой регрессий.

Моки не обращаются к реальному API. Неизвестный mock endpoint отвечает 501 mock_coverage_gap. 401, 403, 404, сеть и 5xx различаются. Отказ доступа не очищает сессию как истёкший токен. Все новые ограничения выполняются в mock handler/service, а не только скрывают кнопку. В будущем backend должен реализовать те же проверки самостоятельно.

В конце: npm test, npm run build, lint с сравнением исходного долга и проверкой изменённых файлов; ручные сценарии текущего подшага. Не выдавать непроверенное за проверенное.

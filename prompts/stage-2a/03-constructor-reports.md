# 2А-3 — сохранить конструктор и отчёты на моках

После 2А-2 прочитай entities/admin/model/adminSlice.ts и types.ts, pages/admin constructor/reports, их widgets/features и docs/stage-2a/legacy-api-map.md. Составь инвентаризацию действующих операций и зависимых metadata вызовов. Не проектируй новый конструктор с нуля.

Реализуй handlers для structure-element-group, structure-element (в том числе multiple-update), structure-element-field, structure-element-object и get-combined-constructor-data ровно по исходным методам, аргументам и DTO. Сохрани существующий редактор, таблицы и отчёты. Нормализованное внутреннее хранение допустимо через adapter, внешняя форма ответа прежняя. Сохраняй связи узел/вкладка/поле/объект и неизвестные данные; после reload информация не пропадает.

get-combined-constructor-data возвращает исходный AdminPanelReport[], а не готовую таблицу: transformResponse уже есть в adminApi. Отчёт читает реальные сохранённые тестовые объекты, учитывает права и выбранные поля. Изменение названия поля не теряет значения по прежнему имени; используй стабильные идентификаторы внутри mock adapter и документированный перевод к legacy форме. Если действующий контракт этого не позволяет — сохрани данные и явно ограничь переименование, не стирай молча.

Удали неоднозначность удаления связанных сущностей: запрет с объяснением либо явное подтверждение каскада и транзакция. Проверяй ссылки на чужую организацию в body/query, а не только organizationId URL. Права редактировать конфигурацию, вводить данные и читать отчёт разделены. Customer не получает конфигурацию и лабораторные объекты через прямой URL/API.

Добавь минимальный GET уведомлений и настройки/metadata, если они действительно запрашиваются оболочкой и мешают этим экранам. Форму ответов бери из notificationSlice/userSlice. Изменения уведомлений реализуй только при объявлении функции рабочей, иначе честно отключи действие с пояснением. Websocket в mock не включай. Не реализуй всю platform-admin ради отсутствия 501 в консоли.

Прогони сквозной сценарий: admin A создаёт узел/вкладку/поля/запись → сохраняет → reload → строит отчёт → пользователь A читает только разрешённое → пользователь B и заказчик получают отказ. Изменения задач из 2А-2 должны сохраниться. Дополнительно проверь поля/типы, которые уже поддерживает нынешний конструктор, включая пустые значения и связи. В конце перечисли непокрытые legacy endpoints и подготовь handoff для 2Б; новую главную не начинай.

Общие условия: React + Tailwind + shadcn + RTK Query + FSD сохраняются. Не переносить все папки, не переписывать задачи/конструктор, не менять production DTO ради удобства моков. Новые proposed endpoints отметить как mock-only. UI получает данные через RTK Query, а не импортирует сиды и handlers. Композиция приложения и запуск MSW — app; доменные типы и API — entities; пользовательские действия — features; shared не импортирует app. Не создавать универсальный движок до появления потребности. Минимальные точечные исправления старого кода допустимы с объяснением и проверкой регрессий.

Моки не обращаются к реальному API. Неизвестный mock endpoint отвечает 501 mock_coverage_gap. 401, 403, 404, сеть и 5xx различаются. Отказ доступа не очищает сессию как истёкший токен. Все новые ограничения выполняются в mock handler/service, а не только скрывают кнопку. В будущем backend должен реализовать те же проверки самостоятельно.

В конце: npm test, npm run build, lint с сравнением исходного долга и проверкой изменённых файлов; ручные сценарии текущего подшага. Не выдавать непроверенное за проверенное. Заполнить docs/stage-2a/report-template.md отдельным отчётом, указать оставшиеся ограничения и изменённые файлы. Следующий подшаг автоматически не начинать.

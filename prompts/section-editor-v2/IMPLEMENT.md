# Задача для Cursor: дизайн создания и редактирования раздела

Ты работаешь в существующем React + Tailwind + shadcn + RTK Query приложении с FSD. Обнови только визуальное оформление страницы создания/редактирования раздела, следуя приложенному макету и docs/section-editor-v2/*.md.

Сначала прочитай AGENTS.md/правила проекта, git status и актуальные SectionEditor, SectionEditorPage, types, rules, API, leave guard, текущие tokens/UI. Сравни с CODE_MAP. Кратко запиши, какие фактические компоненты меняются и где лежат сохраняемые обработчики. Не останавливайся на плане: затем выполни ограниченный редизайн.

Реализация:
1. Расширь локальный контейнер, сгруппируй поля в 3 карточки, выстрой заголовок и панель действий. Не создавай второй заголовок, если текущий shell уже выводит нужный. Не переделывай sidebar по изображению.
2. Отдели визуально сохранение от публикации, сохрани настоящий статус, все действующие предупреждения, ошибки и диалог публикации. Не добавляй новую публикационную политику.
3. Сохрани существующие Input/Label/Textarea/Checkbox и каталог иконок. Не заменяй native select на сложный кастомный компонент без необходимости. Все контролы должны оставаться управляемыми прежним буфером.
4. Добавь локальный неинтерактивный образец оформления справа. Он только читает title/description/iconKey/showCreate/createLabel текущего буфера. Нет новых API-вызовов. Реальный Preview остаётся существующей ссылкой.
5. Сделай адаптивный layout и тёмную тему на текущих токенах. Стили локальные, без глобальных body/button/input/reset. Не добавляй библиотеки и production-картинки.
6. Проверь ACCEPTANCE. Запусти существующие meaningful tests, build, lint; baseline сравни с фактическим состоянием до правок. Не исправляй все старые lint-ошибки. Не добавляй тесты на классы и snapshot-разметку; тест нужен, только если изменено условие поведения, требующее проверки.
7. Сохрани отчёт с файлами, командами, ручными сценариями и честным списком непроверенного. Если браузера нет, не заявляй браузерную приёмку.

Не выполнять commit/push, reset базы, миграции, правки permissions, API, auth, namespace, writer service, маршрутов, рабочих записей или фонового автосохранения. Не откатывать текущие незакоммиченные изменения. Найденные независимые проблемы оформить отдельно и не расширять задачу.

# Обновить только оформление главной inLog

Прочитай текущие правила .cursor, актуальные исходники главной, её дочерних компонентов, последние отчёты и материалы:
@design/home-refresh-v2/home-reference.png
@docs/home-refresh-v2/DESIGN.md
@docs/home-refresh-v2/DO_NOT_BREAK.md
@docs/home-refresh-v2/ACCEPTANCE.md

Пользователь хочет реализовать этот визуальный вариант существующей главной. Это задача оформления, а не изменения прав и архитектуры продукта. Не выполнять commit/push, reset/clean, сброс IndexedDB, установку пакетов или изменение .env. Сохрани текущую незакоммиченную работу. Не заменяй исходники кодом из старых архивов.

1. Найди текущий HomePage/HomeProjectTasks или аналоги. Изучи связи с навигацией, context, permissions, dynamic sections, открытием задач и темами. Зафиксируй git status и baseline команд. Не выводи секреты. Составь краткий список файлов и затем реализуй визуальные изменения, не останавливаясь на плане.

2. Полный референс нельзя использовать как картинку страницы. Всё содержимое, заголовки, бейджи, поля контекста, кнопки, карточки и таблицу реализуй React + Tailwind + shadcn. Только декоративный фон приветствия бери из /images/home-refresh-v2/welcome-background.webp. При его недоступности CSS-градиент и текст остаются рабочими.

3. Сохрани нынешние данные и бизнес-логику. Не меняй условия can/grantAllows/shouldLoadProjectTasks и реестр доступности. Не показывай новые пункты по названию роли или email. Полный доступ owner этим заданием не внедряется и не отменяется. Не меняй backend, mock handlers, repository, миграции, session, маршруты и зависимости.

4. Перестрой только главную: выразительное компактное приветствие с живым именем и подтверждённым контекстом; карточки рабочих разделов, включая все доступные опубликованные разделы; быстрые действия с одним primary; существующие задачи проекта; компактные инструменты настройки. Классифицируй отображение уже отфильтрованного реестра локально на главной, не создавая второй каталог прав и не меняя sidebar. Профиль и уведомления остаются доступны в текущей оболочке.

5. Не фиксируй карточки на количестве «две». На референсе только задачи и отчёты, но реальная организация может иметь больше разделов, один или ни одного. Отсутствующие права, blocked/pending, выбор организации/проекта, loading/error/retry/empty должны работать как раньше. Не показывай данные Б при ожидании данных А. Не маскируй ошибку пустым списком.

6. Таблица задач: текущий запрос/limit/currentData и ссылки сохраняются. Даты и статусы из API, без вшитых примеров, KPI и вычисленной просрочки. Desktop 3 колонки; mobile можно читаемые строки с метаданными. Ссылка «Все задачи» использует действующий workspaceHref. Создание задачи вызывает существующий requestCreateTask и открывает ту же форму. Остальные быстрые действия сохраняют их действующие сценарии.

7. Небольшие UI-компоненты допускаются только если реально упрощают страницу. Сохрани FSD, общие кнопки и иконки lucide. Не добавляй сетевые ресурсы. Используй локальные home tokens/классы; не меняй глобальные primary/background/muted для всего сайта. styles-reference.css — справочник, не обязательный импорт и не повод создавать второй способ темизации.

8. На 1440px основная сетка 2/3 +1/3, на средней ширине адаптируй, на mobile одна колонка. Padding16 mobile/24–32 desktop, нормальный читаемый текст. Иллюстрацию на mobile скрыть. Текст не обрезать fixed-height. Не вводить анимацию, задерживающую действия. Все интерактивные элементы доступны с клавиатуры, фокус виден, нет вложенных ссылок/кнопок. Декор aria-hidden и не перехватывает клики.

9. Прогони проверки ACCEPTANCE.md, npm test и npm run build; lint по изменённым файлам и сравнение общего долга с текущим baseline. Для чистых изменений классов не создавай тесты, повторяющие разметку. Если пришлось менять поведенческий helper, добавь необходимый сценарный тест, а не ослабляй существующий. Проверки браузера и unit разделяй. Непроверенное укажи явно.

10. Сохрани docs/home-refresh-v2/report.md: ветка/HEAD, файлы, что изменено только визуально, какие функции проверены, результаты команд, ограничения, скриншоты desktop и mobile на синтетических данных. Снимки не масштабировать для имитации другого viewport; ограничения инструмента назвать. Не включай реальные токены или личные данные.

Доведи страницу до проверяемого результата. Не начинай редизайн других страниц, новый функционал или конструктор процессов. Commit/push не выполняй.

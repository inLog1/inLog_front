# Подшаг 2. Редактор и понятный режим просмотра

Начинать после принятого списка. Референс:
@design/forms-ux-v2/form-editor-desktop.png.

Прочитай текущие EditorPage/FormEditor/FieldSettings, buffer и leave guard. Не заменяй управление состоянием на новую архитектуру. Выровняй верх страницы и рабочую область по одному левому краю. Заголовок — имя формы вместо общего «Изменить».

Название/описание компактно сверху. Рабочая сетка: список полей слева, настройки справа; на mobile последовательные панели. Список и настройки занимают ширину области, не узкий блок, сдвинутый вправо. Активное поле светло-синее. Удаление — отдельное действие внизу настроек.

Локальный preview переключается без потери buffer/values. «Записи» и «Таблицы» — прежние route links с guard, не притворные вкладки, размонтирующие редактор. Переход к таблицам показывается только по прежним правам; не заводи новый API.

Сохрани текущую публикацию: она может сама сохранить грязный черновик до publish. Изображение с disabled при dirty не является новым правилом. Используй существующий handler; поясни label и две стадии. Если save прошёл, publish отказал, показать правду: черновик сохранён, версия не опубликована. Сводка изменений, expected revisions, busy/double click и ошибки сохраняются.

Локально покажи подтверждённое mock-состояние записи из текущих session flags: при writeLocked или writesUnavailable понятная плашка и disabled edit/save/publish/create действия. Не очищай уже введённый draft. Повторная проверка должна вызвать существующий authoritative status query и обновить соответствующее UI состояние без logout/нового bootstrap, который стирает buffer. Найди текущий предусмотренный механизм. Если его нет, добавь минимальный UI adapter к существующему endpoint; repository/lease не менять и не принуждать владение. Live не вызывает mock endpoint.

Проверь: все существующие типы, порядок и удаление draft поля, 0/false/date, save, publish dirty, publish без права, две стадии ошибки, preview без записи, org switch/back/forward, блокировка после начала редактирования, повтор без потери buffer. Отдельно отсутствие writer API и неизменность сервиса. Для lock использовать тестовые условия на отдельном origin, не отключать защиту.

Отчёт docs/forms-ux-v2/report-02-editor.md.

Общие ограничения: прочитать актуальный код, .cursor и документы пакета; не менять owner policy, can, service, API DTO, immutable versions, storage/namespace/schemaVersion, env и зависимости. Не выполнять commit/push/reset/clean. Не терять незакоммиченную работу. UI не импортирует seed/repository/handlers. Сохранить React + Tailwind + shadcn + RTK Query + FSD и текущие RU/EN/dark режимы.

Сначала коротко перечислить текущие файлы и действующие сценарии, затем реализовать подшаг до проверяемого результата. Не останавливаться после плана. Сравнивать с макетом как с примером, реальные данные и условия берутся из приложения. Картинку не встраивать вместо интерфейса. Не менять соседние страницы и главную.

В конце запустить существующие тесты, build и lint затронутых файлов, сравнить общий долг с текущим baseline. Для изменений только классов не писать тесты, копирующие разметку. Для новых условий доступности/поведения добавить необходимые сценарные тесты. Автотесты и browser перечислить отдельно. Сохранить отчёт по docs/forms-ux-v2/REPORT_TEMPLATE.md. Следующий подшаг автоматически не начинать.

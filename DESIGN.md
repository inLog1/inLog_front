# Визуальные правила

## Оболочка

Сохранить текущий логотип inLog и синий основной акцент. Для светлой темы: фон рабочей области #F5F7FA, белые поверхности и sidebar, основной текст #172235, вторичный #596579, границы около #E2E8F0. Это ориентиры токенов, а не inline-стили. Проверять контраст и тёмные аналоги. Без прозрачного основного secondary-текста.

Desktop: sidebar 232–248px, белая шапка примерно 64px, содержимое с отступами 24–32px. Основные списки/таблицы используют ширину области, а не узкий центрированный контейнер. Обычные формы ввода ограничить примерно 720–800px; конструкторы и матрица прав шире. Один основной H1 на страницу; в шапке breadcrumb.

Sidebar: Главная; Работа — опубликованные разделы организации, задачи, отчёты; Настройка — формы, разделы, доступ и роли. Legacy-конструктор сохранить отдельным подписанным инструментом. Пока нет глобального каталога таблиц, «Табличные представления» ведут к выбору формы через существующий путь или остаются внутри форм; не рисовать мёртвую ссылку ради макета.

Профиль, тема и выход — внизу sidebar/меню пользователя. Уведомления — в шапке. Не повторять их крупными карточками главной. Организация всегда видима; проект показывается для проектных разделов и контекста главной. Никакого нового переключателя корпораций в отдельной установке.

Mobile: первая строка — меню, название, компактные действия; вторая — выбор организации и, если нужно, проекта. Никакой постоянной шапки в три-четыре ряда. Drawer закрывается после перехода. Таблица прокручивается внутри области. На 320px содержимое и кнопки остаются доступны.

Кнопки: одно основное действие primary на рабочую область; вспомогательные outline/ghost. Высота 36–40px desktop, не менее удобного касания mobile. Радиус поверхностей 8–12px, полей 6–8px, тени минимальные. Базовый текст 14–16px, подписи 12–13px, H1 24–28px.

## Главная

Небольшое приветствие и подтверждённый контекст. Главный блок — рабочие разделы, не инструменты разработки. Рядом быстрые действия. Ниже реальные задачи проекта при ready-контексте и праве. Внизу компактные доступные инструменты настройки.

Для суперадминистратора допустим компактный бейдж «Полный доступ в пределах корпорации». Постоянная большая плашка и дублирующий выбор организации не обязательны. Для обычного сотрудника этот блок отсутствует.

Нет рабочих прав в выбранной организации: понятное объяснение, выбор другой доступной организации и информация о назначениях. Не имитировать пустую рабочую главную карточками профиля. Заказчику оставить честное сообщение о неподключённых заявках. Не добавлять случайные KPI, графики и данные.

## Рабочий раздел

Breadcrumb → название раздела → краткое описание. Одна кнопка «Добавить образец» справа desktop/ниже заголовка mobile. Ниже таблица. «Фильтры» с количеством активных условий; «Сбросить» только если есть изменения. Сортировка в компактной панели, а не большой пустой рамке. Итог и пагинация рядом с таблицей. Дата читаемая, UTC обозначен в системной колонке. Статусы — спокойные бейджи.

## Роли

Список на desktop — компактные строки: название, область, число назначений, краткий доступ, действия. Mobile — карточки. Термин «Корпорация», не «Вся установка», в пользовательских подписях. Техническая граница установки объясняется в справке.

Редактор: поля названия/описания/области сверху; категории и поиск слева; одна матрица прав в центре; сводка справа. Матрица: действие / «Выполнять» / «Выдавать другим». Группа каталогов одна, а не два параллельных длинных списка. Категория с несколькими правами раскрывается отдельно. Системная capability суперадмина не становится чекбоксом роли.

Сводка: область, операционные права, делегирование, число затрагиваемых людей. Данные реальные. Sticky-панель «Отмена / Сохранить» не закрывает поля. На mobile категории как select, сводка сворачивается, подписи двух видов прав сохраняются у каждой строки.

Технические resource.action — по раскрытию «Технические сведения», не основной контент. Отказ объясняется причиной: нет права менять роли, нет права выдавать это действие, другая организация, конфликт версии. Не делать глобальное «Выбрать вообще всё». Можно явное действие «Выбрать доступные в группе» отдельно по каждому набору с корректной mixed-семантикой.

Профили разрешений вроде «Читатель» в этом шаге не нужны. Сначала ясная точная матрица без скрытых автоматически включаемых прав.

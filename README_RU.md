Пакет подготовлен 26.10.2026 по исходникам из inlog_pack.7z. Это задания для Cursor и материалы проверки, а не готовые изменения приложения.

## Что делать сейчас

1. Сохранить текущее состояние этапа 1 отдельным коммитом. Не использовать `git add .` вслепую: просмотреть список файлов, исключить .env, секреты, node_modules и результаты сборки. Архив не содержит .git, поэтому заявленные ветку и HEAD независимо подтвердить нельзя.
2. Распаковать этот пакет рядом с проектом. Каталоги docs/stage-2a и prompts/stage-2a можно скопировать в проект с сохранением существующих файлов. Текущий отчёт этапа 1 не заменять.
3. Прочитать REVIEW_RU.md. Передать Cursor только текст START_HERE.md. Он направляет на первый промпт 00. Существующие правила .cursor сохраняются.
4. Принимать работу по одному подшагу. После отчёта и проверок подшага 00 дать промпт 01, затем 02 и 03. Не выполнять весь пакет одним запросом.
5. Материалы verification — доказательства исходной проверки, а не требования к новым результатам. Дополнительный тест из review копируется в проект только на подшаге 00.

## Границы шага

Сначала исправляем проверки доступа и работу сессии, затем соединяем существующие экраны с моками. Новую главную и оформление меню делаем на 2Б. Мастер первичной установки, полноценный редактор ролей, новые конструкторы и настоящий SSO — отдельные шаги.

Порядок: 2А-0 права и сессия → 2А-1 контекст → 2А-2 задачи → 2А-3 конструктор и отчёты → 2Б новая оболочка и главная. После этого развиваем конструкторы форм, таблиц, разделов; конструктор процессов требует отдельной спецификации.

Ваша работа: запускать приложение и принимать сценарии. Cursor: делать ограниченные изменения и отчёт. Григорий: согласовывать контракты будущего API и серверные проверки. Юрий: фиксировать продуктовые решения и приоритеты. Фронтовые моки не заменяют будущую серверную авторизацию.
